- Page templates for every module that has a page on the site, as in WordPress. Put a Blade file in `resources/views/templates/{module}/` (or `templates/all/` for every module, or the same folder of a theme or a skin) with `{{-- Template: Full width --}}` as its first line, and the record form of the module gets a **Template** list: **Default** first, then the files found, with no config; the `atrium.templates` config adds, replaces or hides entries. The list is shown only for a module in `public_urls` that has a template besides the default one. The choice is kept in `admin_record_templates` (a model and an id, like SEO data), so a module needs no column or migration; a model with a column of its own (pages: `template`) says so by implementing `OwnsTemplateColumn` and goes through the same list and the same drawing. The theme draws a record or a section with the template picked, with the variables of the default view and `$defaultView` for `@extends`; a template whose file is gone falls back to the default view, no error. The theme brings **Full width** (`templates/all/full-width`, for any module and any skin); the demo's Contacts page uses it. Pages keep their three templates (`default`, `children`, `landing`) and also get the files found and **Full width**; a page whose template is unknown or gone is drawn with the default one (before, a config with no `default` key drew it with its first template). The choice costs no query on a warm page. The choice is saved with the record: the activity log shows its change, and restoring a version puts its template back. Label in 15 languages. See "Page templates" in [docs/modules.md](docs/modules.md).
