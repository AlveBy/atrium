# Ошибки

[English](errors.md) · [Русский](errors.ru.md)

`alveby/atrium-errors` ловит ошибки сайта и хранит их в собственной базе сайта: исключения PHP, упавшие задачи очереди, упавшие задачи по расписанию и ошибки JavaScript в браузерах посетителей. Ошибки одного вида из одного места складываются в одну строку админки — со счётчиком, трассировкой, запросами и графиком. Когда появляется новая ошибка или возвращается исправленная, приходит письмо или сообщение в Telegram. Всё можно отправлять и в Sentry или GlitchTip, или в любой сервис, для которого вы напишете драйвер.

Это маленький Sentry внутри сайта: ничего не нужно разворачивать и оплачивать, данные остаются на вашем сервере. Когда его станет мало, включите Sentry рядом или вместо.

## Установка

```bash
composer require alveby/atrium-errors
php artisan atrium:module:install alveby/atrium-errors
```

Установка создаёт две таблицы (`error_issues`, `error_events`), добавляет в меню **Состояние сайта → Ошибки**, на рабочий стол — плитку **Ошибки за сутки**, и даёт право просмотра ошибок всем ролям, которым можно менять настройки модуля. Старые события удаляются ночью планировщиком Laravel, поэтому cron должен раз в минуту вызывать `php artisan schedule:run` — как на любом сайте Atrium.

Проверить, что всё работает:

```bash
php artisan atrium:errors:test
```

Тестовая ошибка появится в **Состояние сайта → Ошибки** и во всех остальных включённых драйверах.

## Что ловится

| Источник | Как |
|---|---|
| Исключения PHP на страницах и в командах | обработчик исключений Laravel; то, о чём Laravel и так не сообщает (валидация, 404, вход), пропускается |
| Задачи очереди, упавшие окончательно | событие `JobFailed`, с именем задачи, очередью и подключением |
| Задачи по расписанию, которые упали | событие `ScheduledTaskFailed`, с командой и её расписанием |
| Ошибки JavaScript | небольшой скрипт в страницах, [включается в настройках](#ошибки-javascript) |

Каждое событие хранит цепочку исключений (до трёх предыдущих) с кодом вокруг каждой строки трассировки; запрос — намеренно скупо: адрес без секретных параметров, метод, маршрут, сайт, язык и id вошедшего пользователя; релиз, окружение, версии PHP и Laravel и последние 30 запросов к базе и строк журнала перед ошибкой. Заголовки, куки, тело запроса и IP-адрес не сохраняются никогда.

Сообщить об ошибке самому:

```php
use Atrium\Errors\Errors;

app(Errors::class)->capture($exception, context: ['order' => $order->id]);
```

Исключения из списка `ignore` в `config/atrium-errors.php` не ловятся никогда.

## Как ошибки группируются

Ошибка считается той же, если у неё тот же класс и она случается в том же месте: первые пять кадров вашего собственного кода, по файлу и функции. Номера строк не учитываются — правка выше строки не создаёт новую ошибку; числа, id и значения в кавычках в сообщении тоже. Скомпилированные шаблоны и собранные бандлы узнаются по имени без хеша. Если места по коду не определить, решает сообщение с вычищенными меняющимися частями.

## Экраны админки

**Состояние сайта → Ошибки** — по строке на ошибку: класс и сообщение, где случается, уровень и источник, сколько раз и у скольких пользователей, когда была в последний раз. Кнопки над списком переключают нерешённые, решённые, скрытые и все; фильтры ищут слова в классе, сообщении и месте и сужают список по сайту, релизу, уровню, источнику и адресу. Сортировка — по последнему или первому появлению, по событиям или по пользователям.

Страница ошибки показывает:

- кнопки «Решено», «Решено в следующем релизе», «Скрыть» или «Открыть снова»;
- события, пользователей, первое и последнее появление, первый и последний релиз;
- график по часам за сутки или по дням за 30 дней, с числом на каждом столбике;
- адреса и релизы, где она случается чаще всего;
- трассировку одного события: кадры вашего кода с кодом вокруг, кадры фреймворка — за кнопкой;
- запрос, окружение и то, что происходило перед ошибкой;
- все события, новые сверху; каждое открывает свою трассировку.

Плитка **Ошибки за сутки** на рабочем столе считает события, новые ошибки, вернувшиеся и нерешённые, рисует события по часам и показывает пять самых частых ошибок.

## Статусы и «Решено в следующем релизе»

| Статус | Значит |
|---|---|
| Не решена | Новая или открытая снова. Оповещения приходят |
| Решена | Исправлена. Новое событие открывает её снова и присылает оповещение «вернулась» |
| Скрыта | Известна и безвредна. События считаются, оповещений нет |

**Решено в следующем релизе** — для ошибки, которая исправлена в коде, но ещё не выложена. Ошибка помечается решённой в релизе, который работает сейчас: события этого релиза её не открывают, а первое событие любого другого — открывает. Релиз — это коммит git рабочей копии, или `ATRIUM_RELEASE`, если вы задаёте его в скрипте выкладки, или версия приложения из Composer.

## Оповещения

Оповещения приходят письмом, в Telegram или туда и туда:

- **новая** ошибка;
- ошибка **вернулась** после того, как её отметили решённой;
- **всплеск**: у ошибки за час событий больше порога (по умолчанию 100; 0 выключает всплески).

Каждая ошибка оповещает один раз по каждой причине, всплеск — не чаще раза в час, а все вместе — не больше десяти раз за десять минут, чтобы авария не завалила почту. Письма идут через почтовые настройки админки со своим назначением, поэтому у них может быть свой отправитель. Для Telegram создайте бота через `@BotFather`, добавьте его в чат и впишите в настройки его токен и id чата.

## Драйверы: база, Sentry, журнал

Событие уходит во все включённые драйверы, в каждый отдельно: упавший не мешает остальным, а его ошибка записывается в запасной журнал.

| Драйвер | Что делает |
|---|---|
| `database` | Хранит события в базе сайта для экранов админки. Включён по умолчанию |
| `sentry` | Отправляет события в Sentry, свой Sentry или [GlitchTip](https://glitchtip.com), который говорит на том же протоколе. Нужен только DSN, SDK не нужен |
| `log` | Пишет строку в журнал приложения — для сборщиков журналов, которые его уже читают |

```dotenv
ATRIUM_ERRORS_DRIVERS=database,sentry
ATRIUM_ERRORS_SENTRY_DSN=https://public-key@errors.example.com/7
```

Если `ATRIUM_ERRORS_SENTRY_DSN` пуст, драйвер `sentry` берёт `SENTRY_LARAVEL_DSN` или `SENTRY_DSN`.

## Свой драйвер: Bugsnag, Rollbar, вебхук

Драйвер — это класс, реализующий `Atrium\Errors\Contracts\ErrorReporter`:

```php
namespace App\Errors;

use Atrium\Errors\Contracts\ErrorReporter;
use Atrium\Errors\Event;
use Illuminate\Support\Facades\Http;

final class WebhookReporter implements ErrorReporter
{
    public function report(Event $event): void
    {
        Http::timeout(3)->post('https://hooks.example.com/errors', [
            'id' => $event->id,
            'level' => $event->level,
            'title' => $event->class.': '.$event->message,
            'release' => $event->release,
            'fingerprint' => $event->fingerprint,
        ]);
    }
}
```

Зарегистрируйте его под именем и включите:

```php
// config/atrium-errors.php
'reporters' => [
    'webhook' => App\Errors\WebhookReporter::class,
],
```

```dotenv
ATRIUM_ERRORS_DRIVERS=database,webhook
```

Класс создаётся контейнером, так что конструктор может просить всё, что там зарегистрировано. Событие приходит уже очищенным, после выборки и потолка. `report()` выполняется после того, как ответ ушёл посетителю, или в задаче очереди, поэтому на запрос полагаться нельзя. Бросать исключения можно: ошибка уйдёт в запасной журнал, а остальные драйверы событие всё равно получат.

В `Event` есть `id`, `kind` (`php`, `job`, `schedule`, `browser`, `message`), `level`, `class`, `message`, `exceptions` (у каждого `class`, `message` и `frames`, кадр броска первым), `request` (`url`, `path`, `method`, `route`, `site_id`, `locale`, `user_id`), `context`, `breadcrumbs`, `environment`, `release`, `runtime`, `fingerprint` и `timestamp`.

Для Bugsnag или Rollbar вызовите в `report()` их PHP-клиент: `Bugsnag::notifyError($event->class, $event->message)` или `Rollbar::log($event->level, $event->message, [...])`. Передайте `fingerprint` как их ключ группировки — тогда обе системы будут группировать ошибки одинаково.

## Вместо этого — sentry-laravel

Если вам нужен собственный SDK Sentry (`sentry/sentry-laravel`) ради трассировки производительности, установите его по документации Sentry и не указывайте `sentry` в `ATRIUM_ERRORS_DRIVERS`, чтобы ошибки не уходили дважды. Работать вместе они могут: SDK отправляет в Sentry, модуль хранит свою копию для админки.

## Ошибки JavaScript

Включите в настройках **Ловить ошибки JavaScript на сайте** или **в админке** (или `ATRIUM_ERRORS_BROWSER_SITE=true`, `ATRIUM_ERRORS_BROWSER_ADMIN=true`). Модуль сам добавит небольшой скрипт в каждую полную HTML-страницу — шаблоны и тему править не нужно. Странице с Content-Security-Policy скрипт достаётся с nonce от Vite.

Скрипт отправляет не больше пяти ошибок со страницы и никогда одну и ту же дважды — только сообщение, тип и стек. Адрес добавляет и чистит сервер. Отчёты приходят на `POST /atrium-errors/browser`, который принимает десять в минуту от одного посетителя и не больше 16 КБ каждый.

## Секреты и персональные данные

Перед тем как событие сохраняется или куда-то уходит, оно очищается:

- заголовки, куки, тело запроса и IP-адрес не берутся вовсе;
- значения под ключами, в названии которых есть пароль, секрет, токен, ключ API, авторизация, куки, сессия, CSRF-токен, карта, CVV, IBAN, подпись, DSN, e-mail, телефон, PIN или одноразовый код, заменяются на `[Filtered]` — в контексте и данных задачи, включая ключи вроде `user_password` или `X-Api-Key`, и в параметрах адреса;
- в любом тексте — сообщениях, адресах, запросах к базе, строках журнала — пары вида `password=…` вычищаются; e-mail становится `[email]`, номер карты (проверяется по Луну, так что номер заказа остаётся) — `[card]`, телефон — `[phone]`.

Свои ключи добавляются в `scrub_keys` в `config/atrium-errors.php`.

## Нагрузка: выборка, потолок, очередь

Учёт ошибок не должен ронять сайт вместе с собой:

- **Выборка**: хранить только часть событий, 1–100 процентов (`ATRIUM_ERRORS_SAMPLE_RATE`, по умолчанию 100).
- **Потолок**: не больше стольких событий в минуту на весь сайт (`ATRIUM_ERRORS_PER_MINUTE`, по умолчанию 60); лишнее отбрасывается до всякой работы.
- **Запись потом**: события сохраняются после того, как ответ ушёл посетителю; с `ATRIUM_ERRORS_QUEUE=redis` — через это подключение очереди.
- **Запасной журнал**: если в базу записать нельзя, событие уходит в `storage/logs/atrium-errors.log`, по строке JSON на каждое.
- **Срок хранения**: события старше 90 дней удаляются каждую ночь в 03:40 (`ATRIUM_ERRORS_RETENTION_DAYS`); ошибки, у которых не осталось событий, — вместе с ними.

Ошибка внутри самого модуля записывается в запасной журнал и никогда не пробрасывается дальше.

## Права и сайты

Два права в **Ролях**:

| Право | Даёт |
|---|---|
| `errors.view` — Просмотр ошибок | Список, страницы ошибок, кнопки статусов и плитку на рабочем столе |
| `errors.settings` — Настройки | Настройки модуля: драйверы, DSN, оповещения, выборку |

При установке роли с правом на настройки получают и право просмотра. Одно не включает другое: роль может видеть ошибки, не меняя, куда они уходят, и наоборот.

Администратор, ограниченный частью сайтов, видит только ошибки, случившиеся на этих сайтах, и только их события. Ошибки без сайта (команды, задачи очереди) видят только администраторы всех сайтов.

## Настройки

**Модули → Ошибки → Настройки** в админке; сохранённое там важнее `.env`, который задаёт значения по умолчанию. DSN и токен Telegram лучше держать в `.env`.

| В админке | `.env` | По умолчанию |
|---|---|---|
| Драйверы | `ATRIUM_ERRORS_DRIVERS` | `database` |
| DSN Sentry | `ATRIUM_ERRORS_SENTRY_DSN` | `SENTRY_LARAVEL_DSN`, `SENTRY_DSN` |
| Хранить событий, % | `ATRIUM_ERRORS_SAMPLE_RATE` | 100 |
| Событий в минуту, не больше | `ATRIUM_ERRORS_PER_MINUTE` | 60 |
| Хранить дней | `ATRIUM_ERRORS_RETENTION_DAYS` | 90 |
| Почта для оповещений | `ATRIUM_ERRORS_ALERT_EMAIL` | нет |
| Токен бота Telegram | `ATRIUM_ERRORS_TELEGRAM_TOKEN` | нет |
| Чат Telegram | `ATRIUM_ERRORS_TELEGRAM_CHAT` | нет |
| Оповещать о новых / вернувшихся | | да / да |
| Всплеск: событий в час | | 100 |
| JavaScript на сайте / в админке | `ATRIUM_ERRORS_BROWSER_SITE`, `ATRIUM_ERRORS_BROWSER_ADMIN` | нет / нет |

Только в `.env`:

| `.env` | По умолчанию | Что делает |
|---|---|---|
| `ATRIUM_ERRORS_ENABLED` | `true` | `false`: ничего не ловится, экраны админки остаются |
| `ATRIUM_RELEASE` | коммит git, иначе версия Composer | Релиз, по которому группируются события |
| `ATRIUM_ERRORS_QUEUE` | нет: после ответа | Подключение очереди, через которое сохраняются события |

Остальное — исключения, которые не ловить, дополнительные ключи для очистки, сколько хранить предыстории, сколько строк кода показывать, путь запасного журнала — в `config/atrium-errors.php` после `php artisan vendor:publish --tag=atrium-errors-config`.

## Команды

```bash
php artisan atrium:errors:test           # отправить тестовую ошибку во все драйверы
php artisan atrium:errors:prune          # удалить старые события сейчас
php artisan atrium:errors:prune --days=30
```
