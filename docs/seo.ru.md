# SEO

[English](seo.md) · [Русский](seo.ru.md)

Модуль `alveby/atrium-seo` отвечает за то, что поисковикам нужно от каждой страницы на каждом сайте и языке:

- заголовки и описания по шаблонам;
- canonical и hreflang;
- sitemap на каждый язык;
- отправку в IndexNow;
- разметку schema.org;
- редиректы и журнал 404;
- проверку, которая перечисляет, что исправить, со ссылкой на запись.

В демо он включён на всех сайтах. Сайт без него остаётся с простыми тегами и `sitemap.xml` ядра.

## Установка

```bash
composer require alveby/atrium-seo
php artisan atrium:module:install alveby/atrium-seo
```

В админке появляется группа **SEO**:

| Раздел | Что делает |
|---|---|
| **Проверка SEO** | Список проблем сайта: строка на каждую страницу и проблему |
| **Редиректы** | Список редиректов; у каждого — цепочка, в которую он ведёт |
| **Журнал 404** | Несуществующие адреса, сначала самые частые |
| **Импорт редиректов** | Загрузка редиректов из CSV |
| **Мета страниц** | Мета для адреса, который не запись |
| **Шаблоны мета** | Шаблоны для каждого модуля |

Настройки модуля — в **Модули → SEO**.

Пока модуль не установлен, Composer может его держать, но на сайте ничего не меняется.

## Заголовки и описания

Страница берёт первое найденное значение:

1. **Мета страницы** для её адреса (главная, `/catalog`, `/news?page=2`).
2. Вкладка **SEO** записи.
3. **Шаблон мета** её модуля на языке страницы.
4. Шаблон для **всех модулей** (`*`).
5. Встроенное значение для её вида страницы (товар, статья, раздел, место). Они написаны на всех 15 языках.

Шаблоны подставляют переменные:

| Переменная | Значение |
|---|---|
| `{name}` | Название записи на языке страницы |
| `{site}` | Название сайта |
| `{price}` | Цена с валютой в формате языка страницы (`€49.00`, `49,00 €`) |
| `{section}` | Название раздела |
| `{excerpt}` | Начало анонса или подробного текста без HTML, до 200 знаков |
| `{date}` | Дата публикации в формате языка (`1. März 2026`) |
| `{что угодно}` | Поле записи с таким именем без HTML (`{address}`, `{sku}`) |

**Часть в квадратных скобках выпадает, если переменная внутри пустая.** Переменная вне скобок обязательна. Без неё весь шаблон пустой, и страница берёт название или текст записи.

| Шаблон | Запись | Результат |
|---|---|---|
| `{name}[ — {price}] \| {site}` | Настольная лампа, €49 | `Настольная лампа — €49.00 \| Lumen` |
| `{name}[ — {price}] \| {site}` | Настольная лампа без цены | `Настольная лампа \| Lumen` |
| `[{date}. ]{excerpt}` | Без текста | описания нет (одна дата ничего не говорит) |

Название сайта шаблоны пишут сами, поэтому хвост заголовка ядра (`atrium.seo.title_suffix`) при установленном модуле выключен.

**Следующие страницы списка** получают в заголовке «— страница 2» на языке страницы.

На вкладке SEO каждой записи появляется список **Поисковики**:

- **Индексировать, ходить по ссылкам**;
- **Не индексировать, по ссылкам ходить** (`noindex, follow`);
- **Не индексировать, по ссылкам не ходить** (`noindex, nofollow`).

У закрытой от индекса страницы нет hreflang. Её нет в `sitemap.xml`, и она не уходит в IndexNow.

**Картинка для соцсетей** (`og:image`) берётся по порядку:

1. вкладка SEO;
2. своя картинка записи;
3. картинка сайта по умолчанию из настроек.

## canonical и hreflang

У каждой страницы canonical указывает на неё саму:

- без меток (`utm_*` и подобных);
- с `?page=N` на следующих страницах списка. Каждая страница списка каноническая сама себе, а не первой.

hreflang перечисляет ту же страницу на каждом языке и каждом сайте, где она есть, плюс `x-default`. `x-default` — язык по умолчанию на сайте по умолчанию.

- Общая страница (главная, список) ссылается на все языки всех активных сайтов.
- Запись ссылается только на языки, на которых она написана. У новости на английском и немецком нет французской ссылки.
- Запись одного сайта не видна с других.
- У записи непереводимого модуля (одно название товара на все языки) hreflang нет. Тема даёт ей один адрес.
- Если у двух сайтов общий язык, ссылка ведёт на текущий сайт.
- Сайт на своём домене указан с доменом (`https://shop.example.de/…`), сайт в папке — с папкой (`/site2/…`).

Коды берутся из `hreflang` языка (`pt_BR` → `pt-BR`, `zh_CN` → `zh-CN`).

## sitemap.xml

`/sitemap.xml` — индекс карт, по файлу на язык. Язык больше чем с 50 000 адресов делится на части:

```
/sitemap.xml
/sitemap-en-1.xml
/sitemap-de-1.xml
/sitemap-de-2.xml
```

У каждого адреса есть:

- `<lastmod>` — последнее изменение записи;
- `<xhtml:link rel="alternate">` на другие языки;
- `<image:image>` на её картинки.

У каждого сайта своя карта: `https://shop.example.de/sitemap.xml`, `/site2/sitemap.xml`.

В карту не попадают:

- выключенные и ещё не начавшиеся записи;
- записи с «не индексировать»;
- адреса, у которых в **Мета страниц** стоит noindex;
- старые адреса редиректов.

Файлы кешируются. Сохранение записи, редиректа или мета страницы в админке их пересобирает. Размер части меняет `atrium.sitemap.per_file`.

Откуда берутся адреса:

- записи модулей с `Sitemapable`;
- записи, которые рисует тема;
- классы из `atrium-seo.sitemap_sources` (см. [Авторам модулей](#авторам-модулей)).

## robots.txt и коды подтверждения

Это есть в ядре и работает без модуля:

- `robots.txt` правится у каждого сайта в **Сайты → (сайт) → Код**. Модуль дописывает строку `Sitemap:` со своей картой сайта. Не на боевом сервере сайт отвечает `Disallow: /`, так что тестовая копия в индекс не попадёт.
- Коды **Google Search Console, Яндекс Вебмастера и Bing Webmaster** вписываются у каждого сайта там же. Вставляйте только код из `content="…"`: теги `<meta name="google-site-verification">`, `yandex-verification` и `msvalidate.01` ядро выведет само.

Проверка SEO сообщает об адресах `sitemap.xml`, которые закрыл `robots.txt`.

## IndexNow

Когда запись публикуют или меняют в админке, её адреса на всех языках уходят в Bing и Яндекс через [IndexNow](https://www.indexnow.org/). Поисковики не ждут следующего обхода.

- Настраивать нечего. Ключ выводится из ключа приложения, у каждого сайта свой, и отдаётся по `/{ключ}.txt`.
- **Только на боевом сервере.** Локально и на тестовом ничего не отправляется.
- Адреса уходят после ответа, так что сохранение поисковиков не ждёт. Если поисковик не ответил, это пишется в лог, а сохранение проходит.
- Один и тот же адрес не отправляется чаще раза в 10 минут (`atrium-seo.indexnow.throttle_minutes`).
- Закрытые от индекса, выключенные и записи без публичной страницы ничего не отправляют.
- Выключается у сайта в **Модули → SEO → IndexNow** или везде через `ATRIUM_SEO_INDEXNOW=false`.

Google IndexNow не принимает: он читает `sitemap.xml`.

## schema.org

На каждой странице **один** граф JSON-LD (`<script type="application/ld+json">` с `@graph`). Модули добавляют в него свои узлы и не выводят свой скрипт. Узлы с одинаковым `@id` сливаются.

Встроенные поставщики:

| Узел | На каких страницах | Откуда данные |
|---|---|---|
| `Organization` (или тип из настроек) | Главная | Настройки: название, логотип, телефоны, почта, адрес, профили |
| `WebSite` с `SearchAction` | Главная | Настройки: адрес поиска с `{search_term_string}` |
| `BreadcrumbList` | Все страницы с хлебными крошками | Хлебные крошки темы |
| `Product` с `Offer` | Товар | Цена, валюта, `in_stock`, картинки, артикул, бренд |
| `NewsArticle` | Новость | Название, дата, дата изменения, картинка, организация как издатель |
| `FAQPage` | FAQ и его категории | Вопросы на странице |
| `AggregateRating` и `Review` | Запись с опубликованными отзывами | Модуль отзывов; кладётся в узел товара или в свой узел |
| `LocalBusiness` (или выбранный тип) | Магазин | Название, адрес, телефон, координаты, часы работы |

Настройки в **Модули → SEO** у каждого сайта свои:

- название и тип организации (`Organization`, `Corporation`, `LocalBusiness`, `Store`, `Restaurant`, `Hotel`, `MedicalClinic` и другие);
- логотип, телефоны, почта, адрес и профили (`sameAs`);
- адрес поиска;
- валюта по умолчанию;
- картинка для соцсетей по умолчанию;
- IndexNow вкл./выкл.

Страницу можно проверить в [Google Rich Results Test](https://search.google.com/test/rich-results) или на [validator.schema.org](https://validator.schema.org/). Тесты модуля сверяют каждый узел с типами schema.org (см. [Как проверить свою разметку](#как-проверить-свою-разметку)).

## Разметка своего модуля

Модуль добавляет узлы классом с `Atrium\Seo\Contracts\SchemaProvider`:

```php
use Atrium\Seo\Contracts\SchemaProvider;
use Atrium\Seo\SeoPage;

final class EventSchema implements SchemaProvider
{
    public function nodes(SeoPage $page): array
    {
        if (! $page->record instanceof Event) {
            return [];
        }

        return [[
            '@type' => 'Event',
            '@id' => $page->mainEntityId(),
            'name' => $page->record->translated('name'),
            'startDate' => $page->record->starts_at->toAtomString(),
            'location' => ['@type' => 'Place', 'name' => $page->record->place, 'address' => $page->record->address],
            'organizer' => ['@id' => $page->organizationId()],
        ]];
    }
}
```

Регистрируется в сервис-провайдере модуля: `ConfigList::add()` добавляет его один раз, а простой `config()->push()` после `config:cache` добавил бы второй. Имя класса ничего не загружает: класс поднимается, только когда модуль SEO установлен и рисуется страница, так что зависимости от него нет:

```php
\Atrium\Admin\Support\ConfigList::add('atrium-seo.schema', EventSchema::class);
```

Что `SeoPage` даёт поставщику:

| Член | Значение |
|---|---|
| `$page->record` | Запись, которую показывает страница, или `null` |
| `$page->kind` | `home`, `index` (список), `section`, `record` или `page` |
| `$page->prefix` | Префикс адреса темы (`catalog`, `news`) |
| `$page->url`, `canonical()` | Адрес страницы |
| `$page->breadcrumbs` | `[['label' => …, 'url' => …], …]` |
| `$page->meta` | Итоговые заголовок, описание, картинка, robots |
| `$page->pageNumber` | Страница списка, 1 для первой |
| `$page->language()`, `site()` | Язык и сайт страницы |
| `mainEntityId()`, `organizationId()`, `websiteId()` | Значения `@id` для связи узлов |
| `$page->context` | Что оставили другие части страницы, например вопросы FAQ |

Если поставщик бросил исключение, это пишется в лог и пропадают только его узлы; остальная страница рисуется.

**Чтобы поменять чужой узел**, а не добавить свой, реализуйте ещё и `SchemaEnricher`. Они идут после всех поставщиков и получают весь граф. Так отзывы добавляют рейтинг в товар.

**Вид может добавить узел** для одной страницы:

```blade
@php(app(\Atrium\Seo\SeoPage::class)->addSchema(['@type' => 'VideoObject', 'name' => $video->name, ...]))
```

### Типы для модулей

Узлы ниже проходят валидатор модуля и правила расширенных результатов Google. Скопируйте форму и заполните из своих записей. Обязательные свойства — **жирным**.

**Туры** — `TouristTrip` с `Offer` на каждую дату:

```php
['@type' => 'TouristTrip', '@id' => $page->mainEntityId(),
 'name' => …, 'description' => …, 'touristType' => 'Hikers',
 'itinerary' => ['@type' => 'ItemList', 'itemListElement' => [
     ['@type' => 'ListItem', 'position' => 1, 'item' => ['@type' => 'TouristAttraction', 'name' => 'Первое озеро']],
 ]],
 'offers' => ['@type' => 'Offer', 'price' => '120.00', 'priceCurrency' => 'EUR',
              'availability' => 'https://schema.org/InStock', 'validFrom' => '2026-12-01', 'url' => …],
 'provider' => ['@id' => $page->organizationId()]]
```

**События** — `Event` (или `MusicEvent`, `SportsEvent`, `TheaterEvent`…). Обязательны **`name`**, **`startDate`**, **`location`**. Добавьте `eventStatus` (`https://schema.org/EventScheduled`, `EventCancelled`, `EventPostponed`) и `eventAttendanceMode` (`OfflineEventAttendanceMode`, `OnlineEventAttendanceMode`, `MixedEventAttendanceMode`). У онлайн-события `location` — `VirtualLocation` с `url`.

**Вакансии** — `JobPosting`. Обязательны **`title`**, **`description`** (можно HTML), **`datePosted`**, **`hiringOrganization`**. Добавьте `validThrough`, `employmentType` (`FULL_TIME`, `PART_TIME`, `CONTRACTOR`, `TEMPORARY`, `INTERN`), `jobLocation` (`Place` с `PostalAddress`) или `jobLocationType: TELECOMMUTE` с `applicantLocationRequirements`. `baseSalary` — `MonetaryAmount` с `QuantitativeValue` (`minValue`, `maxValue`, `unitText`: `HOUR`, `MONTH`, `YEAR`). Закрытую вакансию уберите из графа или закройте страницу от индекса.

**Бронирование и отели** — `LodgingBusiness` или `Hotel`, `Hostel`, `Resort`, `BedAndBreakfast`. Обязательны **`name`**, **`address`**. Добавьте `checkinTime`, `checkoutTime`, `starRating` (`Rating`), `amenityFeature` (`LocationFeatureSpecification`), `priceRange`, номера — `containsPlace` → `HotelRoom` с `occupancy` и `bed`. Модуль бронирования, который продаёт даты, добавляет `Offer` на каждый тип номера.

**Медицина** — `MedicalClinic` для клиники и `Physician` для врача. Обязательны **`name`**, **`address`**. `medicalSpecialty` — член перечисления (`https://schema.org/Dermatology`, `Pediatric`, `Cardiovascular`…), плюс `openingHoursSpecification`, у врача — `hospitalAffiliation`. Данные пациентов в разметку не кладите.

**Недвижимость** — `RealEstateListing` для страницы объявления, сам объект в `about` (`Apartment`, `House`, `SingleFamilyResidence`, `Accommodation`). Добавьте `numberOfRooms`, `floorSize` (`QuantitativeValue` с `unitCode: MTK` для м² или `FTK` для фут²) и `address`. Цена — в `offers`; для аренды `UnitPriceSpecification` с `unitCode: MON`.

**Доска объявлений** — сама вещь: `Product` или `Car`/`Vehicle`, с `offers.itemCondition` (`NewCondition`, `UsedCondition`) и `offers.seller` (`Person` или `Organization`). У машины — `brand`, `model`, `vehicleModelDate` и `mileageFromOdometer` (`unitCode: KMT` или `SMI`). Телефон и адрес частного продавца в разметку не выводите: хватит имени и города.

**Блог** — `BlogPosting`. Обязателен **`headline`**. Добавьте `datePublished`, `dateModified`, `author` (`Person` с `url` или `Organization`), `publisher` (`['@id' => $page->organizationId()]`), `image`, `mainEntityOfPage` и `keywords`.

Даты — ISO 8601 (`2026-12-01`, `2026-12-01T19:00:00+01:00`), адреса полные (`https://…`), цены числом (`'120.00'`), валюты ISO 4217 (`EUR`), члены перечислений полным адресом (`https://schema.org/InStock`).

### Как проверить свою разметку

`Atrium\Seo\Schema\Validator` сверяет JSON-LD с типами schema.org из `packages/seo/resources/schema/vocabulary.php`:

- каждый тип известен;
- каждое свойство есть у типа или его родителя;
- есть свойства, которые требуют поисковики;
- адреса, даты, числа, валюты и члены перечислений записаны правильно.

Он возвращает строку на каждую ошибку или пустой список, если всё верно:

```php
use Atrium\Seo\Schema\Validator;

$html = $this->get('/events/launch')->getContent();
preg_match('#<script type="application/ld\+json">(.*?)</script>#s', $html, $m);

$this->assertSame([], Validator::errors($m[1]));
```

Если вашего типа нет в файле, научите валидатор в своих тестах:

```php
Validator::extend(['ExerciseGym' => ['parents' => ['SportsActivityLocation'], 'required' => ['name', 'address']]]);
```

## Редиректы

**SEO → Редиректы** отправляют со старого адреса на новый:

| Откуда | Куда | Код | Что значит |
|---|---|---|---|
| `/old-page` | `/new-page` | 301 | Переехал насовсем; поисковики переносят вес страницы |
| `/sale` | `/catalog` | 302 | На время; старый адрес остаётся в поиске |
| `/blog/*` | `/news/*` | 301 | Целый раздел: `/blog/first` → `/news/first` |
| `/discontinued` | — | 410 | Удалён насовсем; поисковики выкидывают быстрее, чем при 404 |
| `/partner` | `https://partner.example.org/` | 301 | На другой сайт |

Есть ещё 307 и 308 — для форм, которые должны сохранить метод.

- **Регистр и слэш в конце не важны**: `/Old-Page/` совпадает с `/old-page`.
- **Параметры**: `/old` совпадает и с `/old?utm_source=mail`, и `?utm_source=mail` посетителя уходит на новый адрес. Источник с параметрами (`/list?page=2`) совпадает только с ними, в любом порядке.
- **Цепочки проходятся за один переход.** При `/a → /b → /c` посетитель `/a` попадает сразу на `/c`. В списке цепочка видна рядом с редиректом, чтобы её сократить. Код ответа — от первого редиректа.
- **Петли не сохраняются.** Редирект, который вернул бы на свой же адрес (`/c → /a` при уже заведённых `/a → /b → /c`), не сохранится, а форма покажет, какие адреса ходят по кругу. Петлю, попавшую другим путём (база, старый импорт), сайт не исполняет, а проверка SEO о ней сообщает.
- Админка (`/admin`), API и всё, кроме GET и HEAD, никогда не перенаправляются.
- У каждого сайта свои редиректы.
- Список считает переходы по каждому редиректу и показывает последний. Редирект, которым никто не пользовался год, можно удалять.

### Импорт из CSV

Со старыми сайтами приходят сотни редиректов. **SEO → Импорт редиректов → Импорт** принимает CSV:

```csv
source,target,status
/old-page,/new-page
/sale,/catalog,302
/discontinued,,410
```

- Разделитель угадывается: запятая, точка с запятой или табуляция. Файлы Excel с точкой с запятой и BOM подходят как есть.
- Первая строка, где не адрес, считается заголовком.
- Строка без кода берёт код по умолчанию из формы.
- Существующие редиректы не трогаются, если не включено **Перезаписывать**.
- Строки, которые замкнули бы петлю, с неизвестным кодом или без адреса назначения пропускаются. Откройте импорт — там отчёт с номером строки и причиной.

Файл ложится в закрытое хранилище (`storage/app/private/seo-imports`), снаружи его не скачать.

Из командной строки:

```bash
php artisan atrium:seo:redirects:import redirects.csv --site=2 --status=301 --overwrite
```

## Журнал 404

**SEO → Журнал 404** — адреса, которые посетители запрашивали и не нашли:

- строка на адрес;
- сколько раз его запрашивали;
- с какой страницы на него пришли в последний раз;
- когда это было.

**Создать редирект** открывает форму редиректа с заполненным адресом. Когда редирект сохранён, адрес уходит из журнала.

- Запросы `*.map`, `/.well-known/*`, `/wp-*` и `/xmlrpc.php` не пишутся — это боты. Список — в `atrium-seo.not_found.ignore`.
- Журнал держит 5000 последних адресов на сайт (`atrium-seo.not_found.keep`).
- Выключается через `ATRIUM_SEO_404_LOG=false`.

## Проверка SEO

**SEO → Проверка SEO** обходит все публичные страницы сайта на всех языках. Каждая проблема — строка со ссылкой на форму записи, где её исправить:

| Проверка | Когда срабатывает |
|---|---|
| Нет заголовка | Заголовок страницы пуст (нет названия и шаблона) |
| Заголовок как у других страниц | У двух страниц одного языка одинаковый заголовок; в строке названы остальные |
| Слишком длинный заголовок | Больше 60 знаков (`atrium-seo.check.title_max`); поисковики его обрежут |
| Нет описания | Нет описания ни во вкладке SEO, ни в шаблоне, ни в тексте |
| Описание как у других страниц | У двух страниц одного языка одинаковое описание |
| Нет H1 | У записи нет названия на этом языке, и у страницы нет заголовка |
| Картинка без alt | `<img>` в тексте без `alt` или с пустым |
| Тяжёлая картинка | Картинка в тексте или у записи больше 300 КБ (`atrium-seo.check.image_max_kb`) |
| Закрытая страница в sitemap | Адрес из `sitemap.xml`, который закрыл `robots.txt` |
| Битая ссылка | Ссылка в тексте на адрес сайта, где нет ни страницы, ни редиректа, ни маршрута, ни файла |
| Цепочка редиректов | Редирект ведёт в другой редирект |
| Петля редиректов | Редиректы ходят по кругу |

Клик по названию проверки оставляет только её (`?check=title_long`).

Проверка запускается при открытии списка, если содержимое изменилось с прошлого раза или прошёл час. На большом сайте выключите это через `ATRIUM_SEO_CHECK_INLINE=false` и поставьте команду в расписание:

```php
// routes/console.php
Schedule::command('atrium:seo:check')->dailyAt('04:00');
```

```bash
php artisan atrium:seo:check            # все сайты
php artisan atrium:seo:check --site=2   # один сайт
```

## Настройки

`php artisan vendor:publish --tag=atrium-seo-config` копирует `config/atrium-seo.php`:

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `kinds` | каталог, новости, магазины, FAQ | Модель → вид страницы, для шаблонов по умолчанию |
| `schema` | встроенные поставщики | Классы `SchemaProvider` |
| `sitemap_sources` | `[]` | Классы `SitemapSource` |
| `indexnow.enabled` | `ATRIUM_SEO_INDEXNOW`, true | IndexNow вкл./выкл. |
| `indexnow.endpoints` | Bing, Яндекс | Куда отправлять |
| `indexnow.throttle_minutes` | 10 | Не отправлять адрес повторно в течение этого времени |
| `not_found.enabled` | `ATRIUM_SEO_404_LOG`, true | Журнал 404 вкл./выкл. |
| `not_found.ignore` | адреса ботов | Пути, которые не пишутся; `*` — что угодно |
| `not_found.keep` | 5000 | Сколько строк держать на сайт |
| `check.inline` | `ATRIUM_SEO_CHECK_INLINE`, true | Запускать проверку при открытии списка |
| `check.stale_minutes` | 60 | Насколько старым может быть прошлый прогон |
| `check.title_max` | 60 | Самый длинный заголовок |
| `check.image_max_kb` | 300 | Самая тяжёлая картинка |

Интерфейс и шаблоны по умолчанию — на 15 языках. `php artisan vendor:publish --tag=atrium-seo-lang` копирует их для правки.

## Авторам модулей

**Шаблоны по умолчанию для своего вида страниц.** Назовите вид для своей модели и положите `lang/{язык}/templates.php`, или возьмите вид модуля (`product`, `article`, `section`, `place`, `default`):

```php
config()->set('atrium-seo.kinds.'.Tour::class, 'product');
```

**Страницы в sitemap.** Записи модели с `Atrium\Admin\Contracts\Sitemapable` или те, что рисует тема, там уже есть.

- Для их картинок реализуйте `Atrium\Seo\Contracts\SitemapImages`. Без него модуль берёт `detail_picture`, `preview_picture`, `picture`, `image`, `photo`, `cover`, `photos` и `gallery`.
- Для адресов, которые не записи (дни календаря, страница тега), добавьте `SitemapSource`:

```php
final class CalendarDays implements SitemapSource
{
    public function urls(string $language): iterable
    {
        foreach ($this->days() as $day) {
            yield ['loc' => url("/events/{$day->format('Y-m-d')}"), 'lastmod' => $day->toAtomString()];
        }
    }
}

\Atrium\Admin\Support\ConfigList::add('atrium-seo.sitemap_sources', CalendarDays::class);
```

**Хуки**, которыми пользуется модуль, — чтобы ваш модуль встретился с ним, не завися от него:

| Хук | Вид | Что несёт |
|---|---|---|
| `atrium.head` | фильтр, ядро | HTML в `<head>` публичных страниц |
| `atrium.seo.fields` | фильтр, ядро | Поля вкладки SEO каждой записи |
| `atrium.sitemap.entries` | фильтр, ядро | Адреса записи в sitemap; `[]` — убрать, или добавить `images` |
| `atrium.seo.schema` | фильтр | Классы поставщиков для страницы |
| `atrium.record.saved` | действие, ядро | Отправляет адреса записи в IndexNow |
