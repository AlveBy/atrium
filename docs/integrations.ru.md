# Интеграции

[English](integrations.md) · [Русский](integrations.ru.md)

`alveby/atrium-integrations` — небольшая основа, на которой стоят коннекторы Atrium: 1С, Битрикс24, а позже amoCRM, «МойСклад» и другие. Она даёт каждому коннектору три вещи, чтобы не писать их заново:

- **задание очереди с повторами**: вызов другой системы, который не удался, повторяется через 10 секунд, минуту, пять минут и четверть часа — всего пять попыток;
- **журнал обмена** в админке: когда, какой коннектор, что делал, с чем, чем закончилось и, если плохо, почему;
- **оповещение администраторов**, когда коннектор сдался.

Коннектор (Битрикс24, 1С) работает и без неё, но тогда у него нет экрана с историей: строки уходят в журнал приложения. Ставьте её первой.

## Установка

```bash
composer require alveby/atrium-integrations
php artisan atrium:module:install alveby/atrium-integrations
```

Очередь должна работать (`php artisan queue:work` или настройка хостинга через supervisor/cron), а cron — вызывать `php artisan schedule:run` каждую минуту. При `QUEUE_CONNECTION=sync` вызов делается прямо во время запроса и не повторяется.

## Журнал обмена

**Журнал обмена** в меню показывает все строки, новые сверху. В строке:

| Колонка | Что значит |
|---|---|
| Когда | Дата и время попытки |
| Интеграция | `bitrix24`, `1c`, … |
| Действие | Что делали: `lead.add`, `catalog.import`, … |
| О чём | С чем делали, словами: «Заявка с формы №12» |
| Результат | **Выполнено**, **Ошибка, повторим** (попытки ещё будут) или **Ошибка** (сдался) |
| Ошибка | Почему, если сбой |

Откройте строку — увидите весь текст, номер попытки и сколько миллисекунд занял вызов. Список можно сузить по результату или по интеграции; ненужные строки удаляются. Строки старше 90 дней стираются каждую ночь (число задаётся в настройках модуля).

Тексты обрезаются на 2000 символах. Коннектор называет свои секреты (адрес вебхука, пароль), и во всём, что пишется в журнал, они заменяются на `***` — экран безопасно показать коллеге или приложить к обращению.

## Повторы

Задание коннектора пробуется пять раз. После сбоя оно ждёт 10 секунд, потом 60, 300 и 900, и каждая попытка оставляет строку: **Ошибка, повторим** у первых четырёх, **Ошибка** у последней. Если попытка удалась, задание выполнено, и строка это говорит. Задание, зависшее дольше минуты, останавливается и считается неудачной попыткой.

Паузы — в `config/atrium-integrations.php` (`backoff`); опубликуйте его командой `php artisan vendor:publish --tag=atrium-integrations-config`.

## Оповещения

Когда последняя попытка не удалась, администраторам уходит письмо: какая интеграция, что не смогла сделать, с чем, ошибка, сколько было попыток и ссылка на журнал. Оно идёт на адреса из **Модули → Интеграции → E-mail для оповещений**, а если их нет — всем активным суперадминистраторам.

Чтобы коннектор, лежавший всю ночь, не прислал письмо на каждую запись, одна интеграция говорит не чаще **раза в час** (`alert_interval`, минуты, в конфиге или `ATRIUM_INTEGRATIONS_ALERT_INTERVAL`). В журнале все сбои остаются.

У письма назначение `integrations`: модуль почты, если он установлен, отправит его с ящика, выбранного для этого. Письмо, которое не удалось отправить, записывается в журнал приложения только видом ошибки и ничего больше не ломает.

## Настройки

**Модули → Интеграции**:

- **E-mail для оповещений**: один или несколько адресов через запятую или с новой строки. Пусто — все активные суперадминистраторы.
- **Хранить журнал, дней**: по умолчанию 90 (`ATRIUM_INTEGRATIONS_RETENTION_DAYS`).

## Свой коннектор на этой основе

Наследуйте `Atrium\Integrations\Jobs\IntegrationJob`:

```php
use Atrium\Integrations\Jobs\IntegrationJob;

final class SendOrder extends IntegrationJob
{
    public function __construct(private readonly int $orderId) {}

    protected function integration(): string { return 'moysklad'; }
    protected function action(): string { return 'order.add'; }
    protected function subject(): ?string { return "Заказ №{$this->orderId}"; }
    protected function secrets(): array { return [Setting::get('moysklad.token', '')]; }

    protected function perform(): ?string
    {
        // вызвать API; при ошибке бросить исключение
        return 'Заказ создан: '.$id;   // попадёт в «Что сделано»
    }
}

SendOrder::dispatch($order->id)->afterCommit();
```

Любое исключение из `perform()` — неудачная попытка. То, что метод вернул, записывается как «что сделано».

Работа вне очереди (1С сама обращается к сайту, сайт отвечает сразу) пишет строки сама:

```php
use Atrium\Integrations\Enums\{Direction, Status};
use Atrium\Integrations\Exchange;

app(Exchange::class)->record('1c', 'catalog.import', Status::Failed,
    subject: 'import.xml', error: 'Не удалось прочитать файл', direction: Direction::In);
```

Строка со `Status::Failed` тоже оповещает администраторов с тем же часовым ограничением. Если модуль не установлен, `record()` пишет в журнал приложения, и коннектор продолжает работать.

## Хуки

| Хук | Вид | Аргументы |
|---|---|---|
| `atrium.integrations.failed` | событие | `ExchangeLog` со сбоем; срабатывает при каждом окончательном сбое, даже когда письмо придержано часовым ограничением, — так на него может подписаться другой канал (мессенджер) |

## Команды

```bash
php artisan atrium:integrations:prune
```

Удаляет строки журнала старше срока хранения; планировщик запускает её каждую ночь в 03:41.
