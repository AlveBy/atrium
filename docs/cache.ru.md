# Кеш

Atrium держит публичные страницы быстрыми, даже когда у записи десятки свойств, связей, картинок и переводов. Идея:

- список или фильтр спрашивает у базы **только ID** (и общее число) и запоминает ответ;
- каждая запись рисуется из своей **карточки** — закешированного массива со всем, что показывает страница; карточки страницы приходят **одним multi-get**, а недостающие собираются вместе, за несколько запросов, сколько бы их ни было;
- сохранение сбрасывает ровно те карточки и списки, которых оно касается, поэтому редактор видит правку сразу.

На тёплом кеше страница товара и страница списка не делают ни одного запроса. Кеш целых страниц для анонимных посетителей (по умолчанию выключен) пропускает ещё и работу шаблонов.

Кеш работает на любом хранилище Laravel. **Рекомендуется Redis**.

## Хранилища

| Хранилище | Как сбрасывается группа | Заметки |
|---|---|---|
| `redis` | теги | Рекомендуется: быстрый multi-get, теги, размер в админке. |
| `memcached` | теги | Тоже подходит. |
| `file`, `database` | ключи версий | Работает; каждая карточка — файл или строка. |
| `array` | теги | Только для тестов: живёт один запрос. |

Кеш записей берёт хранилище приложения по умолчанию. Чтобы дать ему своё, задайте `ATRIUM_CACHE_STORE=redis` (хранилище из `config/cache.php`). Для Redis:

```dotenv
CACHE_STORE=redis
REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
```

Хранилище без тегов получает **ключи версий**: в каждый ключ входит отметка из нескольких счётчиков (`all`, `site:{id}`, `card:{Class}`, `list:{Class}`), а сбросить группу — значит увеличить её счётчик. Старые записи больше не читаются и истекают по TTL. `ATRIUM_CACHE_STRATEGY=versions` включает этот способ и на Redis.

## Как подключить модуль

Добавьте модели интерфейс `Cacheable` и трейт `CachesRecords`:

```php
use Atrium\Admin\Cache\CachesRecords;
use Atrium\Admin\Contracts\Cacheable;

class Product extends Model implements Administrable, Cacheable
{
    use CachesRecords, HasAdminSeo, InteractsWithAdmin, Translatable;
}
```

Для большинства моделей этого достаточно. Карточка собирается по полям админки:

- все колонки, переводы как есть (в карточке запись на всех языках);
- связи за `BelongsToField`, `BelongsToManyField` и похожими полями, загруженные сразу для всех недостающих карточек;
- SEO, картинки и галереи (с уменьшенными копиями), публичный адрес;
- то, что добавляют расширения (тема кладёт готовое представление записи).

Чтобы назвать связи самому, переопределите `cacheRelations()`:

```php
public function cacheRelations(): array
{
    return ['brand', 'stores', 'section'];
}
```

Связанная модель, сохранения которой должны доходить до карточки, — **зависимость**: в отметку карточки входит её счётчик списков, поэтому бренд, переименованный в админке, пересобирает карточки товаров с ним при следующем чтении, не раньше. Связи с той же моделью (похожие товары, родительская страница) зависимостями не считаются: сохранение сбрасывает карточки записей, которые её показывают, — их находит один запрос.

Строке, которая принадлежит другой записи через morph-пару (SEO, slug), нужен трейт `TouchesOwner`: её сохранение сбросит карточки владельца. Модель может и сама перечислить владельцев в `cacheTouches()`.

## Списки

Спросите ID, запомните их и рисуйте записи из карточек:

```php
// ID и общее число одной страницы: один запрос при промахе, ни одного при попадании.
$page = Product::query()->where('active', true)->orderBy('sort')->cachedIds(perPage: 20, page: 2);
$page->ids;   // [12, 7, 31, …]
$page->total; // 4310

// То же самое пагинатором из карточек.
$products = Product::query()->where('active', true)->orderBy('sort')->cachedPaginate(20);

// Все подходящие записи карточками (без страниц).
$questions = Question::query()->where('category_id', $id)->orderBy('sort')->cachedCards(dependsOn: [Category::class]);
```

Ключ списка — хеш SQL с параметрами, страницы, сайта и языка. Он сбрасывается, когда сохраняется, удаляется или восстанавливается любая запись модели, а также когда меняется модель из `dependsOn` (укажите её, если запрос соединяет или фильтрует по другой таблице).

Время в запросе списка округляется вниз до минуты (`RecordCache::now()`), поэтому `active_from <= now()` даёт один ключ 60 секунд. Используйте его вместо `now()` в публичных запросах:

```php
->where('active_from', '<=', app(RecordCache::class)->now())
```

## Чтение карточек

```php
$card = Product::cached(42);                 // одна карточка или null
$cards = Product::cachedMany([42, 7, 31]);   // в заданном порядке, ненайденные пропущены

$card->name;                // на текущем языке, с запасным
$card->get('price');
$card->relation('brand');   // модель или коллекция, собранная из карточки
$card->seo('title');
$card->picture('preview_picture', 'detail_picture');
$card->media('photos');     // [['url' => …, 'thumbnails' => …], …]
$card->url();
$card->extra('theme');      // то, что положило расширение
$card->model();             // модель, заполненная из карточки, со связями (без запроса)
```

Язык по умолчанию — текущий; другой передаётся вторым аргументом.

`model()` нужна там, где шаблон ждёт модель. Её не сохраняют: она собрана из кеша.

## Другие значения: remember()

Для всего остального, что берётся из базы (меню, дерево, сводка оценок), используйте `remember()` и назовите модели, которые оно читает:

```php
$tree = app(RecordCache::class)->remember(Page::class, 'page-tree', fn () => $this->buildTree());
$summary = app(RecordCache::class)->remember([Review::class, Product::class], 'summary:'.$id, fn () => …);
```

Значение сбрасывается, когда меняется любая из этих моделей. Оно хранится отдельно для каждого сайта, если не передать `perSite: false`. Храните простые значения (массивы, скаляры): модели в кеше медленно распаковываются и легко устаревают.

Вместо модели можно назвать что угодно: `remember(Settings::class, 'settings:'.$module, …)` сбрасывается вызовом `flushClass(Settings::class)`. Так читаются настройки модулей, поэтому прогретая страница вообще не обращается к базе.

## Когда кеш сбрасывается

Сохранение, удаление или восстановление кешируемой модели через Eloquent (админка, API, MCP, ваш код):

- сбрасывает карточки записи на всех сайтах и языках;
- сбрасывает карточки записей той же модели, которые её показывают (похожий товар, дочерняя страница);
- увеличивает счётчик списков модели: её списки, значения `remember()` с ней и зависящие от неё карточки пересоберутся при следующем чтении.

Сохранение сайта сбрасывает его карточки (его домены есть в каждом адресе), сохранение языка — всё. Если сохранение идёт внутри транзакции, карточки сбрасываются ещё раз после коммита, чтобы запрос посередине не оставил старую строку.

Код, который пишет в обход Eloquent (`DB::table()->update()`, `insert()`), должен сказать об этом сам:

```php
app(RecordCache::class)->flushClass(Product::class); // одна модель
app(RecordCache::class)->flushSite($siteId);         // один сайт
app(RecordCache::class)->flushAll();                 // всё
```

Кроме того, карточки истекают по TTL (по умолчанию сутки), так что пропущенный сброс со временем исправляется сам.

## Импорт

Тысячи сохранений подряд не должны тысячи раз сбрасывать кеш. Оберните импорт:

```php
app(RecordCache::class)->bulk(function () {
    foreach ($rows as $row) {
        Product::updateOrCreate(['xml_id' => $row['id']], $row);
    }
});
```

Внутри `bulk()` сохранения только отмечают затронутые модели; в конце каждая сбрасывается один раз. Импорт, который пишет через `DB::table()`, передаёт `everything: true`, и в конце один раз сбрасывается весь кеш. Так делает мигратор из Битрикса.

## Кеш страниц

Для посетителей без входа можно хранить страницу целиком: второй посетитель получает её из хранилища, контроллер не запускается.

```dotenv
ATRIUM_PAGE_CACHE=true
```

- Ключ — адрес (схема, хост, путь, отсортированные параметры) и сайт; язык входит в адрес.
- Только `GET` и `HEAD`, только HTML-ответы `200`; никогда — админка, вошедший администратор или пользователь, Inertia и ajax, страница, поставившая свою куку или передавшая ошибки или старый ввод, пути из `atrium.cache.pages.except`. Ответ с `Cache-Control: no-store` или заголовком `X-Atrium-No-Cache` не хранится.
- **Токены форм**: CSRF-токен в сохранённой странице на выходе заменяется на токен текущего посетителя, формы продолжают работать.
- Сохранённая страница действительна, пока не изменились карточки, списки и модели, которые она читала: сохранение сбрасывает её сразу. Модели, прочитанные иначе, перечисляются в `atrium.cache.pages.depends_on`.
- В ответе есть `X-Atrium-Cache: HIT` или `MISS`.

Включайте, проверив, что ни одна страница не показывает посетителю без входа что-то личное (счётчик корзины, «вы смотрели»). Такую страницу внесите в `except` или отправьте заголовок из её контроллера:

```php
return response()->view('cart')->header('X-Atrium-No-Cache', '1');
```

Компонент, который рисует что-то для одного посетителя, где бы он ни стоял, вызывает вместо этого `app(RecordCache::class)->dontKeepPage()`. Так делает встроенная капча-картинка: на её вопрос можно ответить один раз, поэтому страница с ней не сохраняется.

## CDN

Сохранённые страницы отдаются с `ETag` и `Last-Modified`; на запрос с совпавшим `If-None-Match` приходит `304 Not Modified`.

- Страница без токена формы: `Cache-Control: public, max-age=0, s-maxage=60`. CDN может держать её `ATRIUM_PAGE_CACHE_SHARED_MAX_AGE` секунд, браузер каждый раз спрашивает заново.
- Страница с токеном формы: `Cache-Control: private, no-cache`. Общая копия отдала бы токен одного посетителя другому.

Группа `web` в Laravel открывает сессию каждому посетителю, поэтому в каждом ответе есть `Set-Cookie`, а большинство CDN не хранят ответ, ставящий куку. Либо настройте CDN не обращать внимания на куку сессии на публичных путях, либо отдавайте публичные страницы без сессии. Atrium не очищает CDN после сохранения: границу устаревания задаёт короткий `s-maxage`.

## Прогрев, экран в админке и строка отладки

После выкладки или очистки кеша:

```bash
php artisan atrium:cache:warm            # главная и первая страница каждого списка, все сайты и языки
php artisan atrium:cache:warm --records  # плюс карточка каждой записи каждого кешируемого модуля
php artisan atrium:cache:warm --site=main
```

Модуль добавляет свои страницы через `app(RecordCache::class)->warmUsing(fn (string $language): iterable => [...])`.

**Админка → Кеш** (для суперадминов) показывает долю попаданий с последнего сброса, хранилище и есть ли у него теги, число записей и их размер (Redis, файлы и база) и очищает один модуль, один сайт или всё.

В локальном окружении с `APP_DEBUG=true` у каждой публичной страницы есть заголовок `X-Atrium-Debug` и строка внизу экрана:

```
queries=3 (2.1 ms); cache hits=21 misses=0; page cache=off; 18.4 ms
```

`ATRIUM_CACHE_DEBUG=false` её скрывает.

## Настройки

`config/atrium.php` → `cache`:

| Ключ | Env | По умолчанию | |
|---|---|---|---|
| `enabled` | `ATRIUM_CACHE_ENABLED` | `true` | Выключен: карточки собираются при каждом чтении, ничего не хранится. |
| `store` | `ATRIUM_CACHE_STORE` | хранилище по умолчанию | Хранилище из `config/cache.php`. |
| `strategy` | `ATRIUM_CACHE_STRATEGY` | `auto` | `auto` (теги, где они есть) или `versions`. |
| `ttl.cards` | `ATRIUM_CACHE_TTL_CARDS` | `86400` | Секунды. |
| `ttl.lists` | `ATRIUM_CACHE_TTL_LISTS` | `3600` | Секунды; и для `remember()`. |
| `ttl.pages` | `ATRIUM_CACHE_TTL_PAGES` | `600` | Секунды. |
| `time_step` | | `60` | До скольких секунд округляется `RecordCache::now()`. |
| `stats` | | `true` | Считать попадания и промахи для экрана в админке. |
| `ignore` | | | Модели, сохранения которых не трогают кеш. |
| `pages.enabled` | `ATRIUM_PAGE_CACHE` | `false` | Кеш страниц. |
| `pages.shared_max_age` | `ATRIUM_PAGE_CACHE_SHARED_MAX_AGE` | `60` | `s-maxage` для CDN. |
| `pages.except` | | `[]` | Пути, которые не хранятся, в виде шаблонов `Request::is()`. |
| `pages.depends_on` | | `[]` | Модели, сохранение которых сбрасывает все страницы. |
| `debug` | `ATRIUM_CACHE_DEBUG` | `true` | Строка отладки (локально, с `APP_DEBUG`). |

## Замер

`packages/theme/tests/CacheBenchmarkTest.php` заполняет каталог из 10 000 товаров по 40 свойств (16 строк, 10 чисел, 6 списков, 4 флажка, 2 текста, 2 ссылки на бренд), с переведёнными названием, кодом и текстом, тремя похожими товарами, тремя картинками и SEO, и открывает через тему страницу списка и страницу товара с выключенным, холодным и тёплым кешем и с кешем страниц:

```bash
ATRIUM_BENCHMARK=1 vendor/bin/phpunit packages/theme/tests/CacheBenchmarkTest.php
```

`DB_CONNECTION` выбирает базу, как и для остальных тестов, `ATRIUM_BENCHMARK_STORE` — хранилище, `ATRIUM_BENCHMARK_PRODUCTS` — число товаров. Тест падает, если страница списка на 250-й странице стоит больше запросов, чем на первой, тёплая страница списка или товара делает больше двух запросов, а сохранённая страница — хотя бы один.

Результаты на 17.11.2026 (PHP 8.4, MySQL 8.4 и PostgreSQL 17 в Docker, Redis 7, медиана пяти запросов; число запросов, затем процессорное время PHP):

| Страница | Кеш выключен | Холодный кеш | Тёплый кеш | Кеш страниц |
|---|---|---|---|---|
| MySQL, список, стр. 1 | 3 запр., 6,8 мс | 7 запр., 39,0 мс | **0 запр.**, 7,6 мс | **0 запр.**, 1,2 мс |
| MySQL, список, стр. 250 | 3 запр., 6,0 мс | 7 запр., 38,9 мс | **0 запр.**, 8,2 мс | **0 запр.**, 1,2 мс |
| MySQL, товар | 6 запр., 7,7 мс | 6 запр., 11,0 мс | **0 запр.**, 4,9 мс | **0 запр.**, 1,4 мс |
| PostgreSQL, список, стр. 1 | 3 запр., 7,3 мс | 7 запр., 48,3 мс | **0 запр.**, 12,1 мс | **0 запр.**, 1,3 мс |
| PostgreSQL, список, стр. 250 | 3 запр., 7,3 мс | 7 запр., 46,9 мс | **0 запр.**, 15,7 мс | **0 запр.**, 1,7 мс |
| PostgreSQL, товар | 6 запр., 13,7 мс | 6 запр., 17,0 мс | **0 запр.**, 7,7 мс | **0 запр.**, 1,7 мс |

«Кеш выключен» — это тема, которая читает базу напрямую, как до кеша. Холодный список стоит больше запросов, потому что собирает карточку целиком (бренды, похожие товары, SEO). Страница товара потом читает её даром. На 1-й и 250-й странице запросов столько же. С файловым хранилищем запросов столько же, а процессорного времени примерно вдвое больше.

Как читать: кеш убирает походы в базу. На тёплом кеше страница не спрашивает у базы ничего, и время перестаёт зависеть от нагрузки на базу и от расстояния до неё. Холодная карточка стоит около 2 мс PHP на запись, один раз. Тёплый список распаковывает 20 карточек и тратит на PHP примерно столько же, сколько чтение 20 строк. Кеш страниц пропускает контроллер и шаблоны: около 1 мс.

Тест печатает и полное время. В него входят база и хранилище, поэтому оно зависит от нагрузки на машину и сравнимо только внутри одного прогона.
