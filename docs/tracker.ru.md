# Трекер

[English](tracker.md) · [Русский](tracker.ru.md)

`alveby/atrium-tracker` ведёт работу команды в админке: проекты, задачи в них, комментарии, историю изменений и письмо тому, кому задачу поручили. Это маленький Jira. Им пользуются администраторы и только они: что кому видно и можно, решают их роли и права, на сайт из этого ничего не попадает.

## Дорожная карта

Цель — то, что Jira и Tempo делают для команды, внутри панели Atrium, по этапам. Каждый этап — отдельный pull request, и каждый опирается на то, что в Atrium уже есть, а не пишет это заново. Jira Service Management (портал заявок) и Confluence не делаем, пока об этом не попросят.

Правила для всех этапов:

- **Данные, не код.** Типы задач, статусы, переходы, приоритеты, резолюции, типы связей и поля — это записи, которые правит администратор, а не enum'ы и не класс на каждый тип. Встроенные — записи, созданные при установке. Благодаря этому трекер потом переедет на конструктор Atrium.
- **Плагины с первого дня.** Всё, что выше основы, регистрируется через тот же реестр, что и плагин (условия, валидаторы и пост-функции переходов, триггеры и действия автоматизации, функции языка запросов, панели карточки задачи, гаджеты дашборда, отчёты, вкладки проекта), так что API проверяется встроенными возможностями. Плагин — Composer-пакет, который регистрируется в сервис-провайдере и включается и выключается в настройках; см. [tracker-plugins.ru.md](tracker-plugins.ru.md).
- **Бизнес-логика в сервисах, не в моделях**, чтобы правило или плагин могли её вызвать; поля моделей один к одному ложатся на поля сущности.
- **Правила автоматизации хранятся деревом данных** (когда → если → сделать), а не кодом PHP.

|---|---|---|---|
| 1 | **Основа** | Проекты (ключ, руководитель, категория), сквозная нумерация `PROJ-123`, типы задач с иерархией (эпик, история, задача, баг, подзадача и свои), приоритеты, резолюции, компоненты, версии, метки, связи задач (блокирует, связана, дублирует, клон), наблюдатели, комментарии с @упоминаниями, вложения, история задачи | Свои поля (`custom-fields`) для полей задач и проектов; история изменений и журнал (#115, #117); хуки и каталог событий (#118, #120); импорт и экспорт; роли и права |

## Установка

```bash
composer require alveby/atrium-tracker
php artisan atrium:module:install alveby/atrium-tracker
```

В меню появятся три раздела в группе **Трекер**: **Проекты**, **Задачи** и **Комментарии к задачам**. Для писем нужна рабочая почта (`MAIL_*` в `.env`); без неё трекер работает, но писем не шлёт.

## Проекты

У проекта есть название, **ключ**, описание, руководитель и участники.

- Ключ — от двух до десяти заглавных латинских букв или цифр, первая буква (`SHOP`, `WEB2`), уникальный. По нему нумеруются задачи: `SHOP-1`, `SHOP-2` … Номер не повторяется, даже когда задачу удалили.
- **Участники** — администраторы, которые работают в проекте. Если они указаны, задачу можно поручить только им и руководителю; если нет — любому активному администратору.
- В **архивный** проект новые задачи не попадают, и в выборе проекта на форме задачи его нет; задачи остаются.

## Задачи

| Поле | Что значит |
|---|---|
| Проект | Где живёт задача. Архивный выбрать нельзя |
| Тип | Один из [типов](#типы-статусы-приоритеты-и-решения): Задача, Ошибка, История, Эпик, Подзадача или свой |
| Название | До 255 символов |
| Описание | Текст, HTML или визуальный редактор |
| Статус | Один из [статусов](#типы-статусы-приоритеты-и-решения) |
| Приоритет | Самый низкий, Низкий, Средний, Высокий, Самый высокий: стрелка и слово, не только цвет |
| Исполнитель | Активный администратор |
| Родительская задача | Подзадача задачи или задача эпика, в том же проекте |
| Метки | Любые слова, до 20 |
| Срок | Задача после него и не завершённая помечается как **просроченная** |
| Оценка | Часы, до двух знаков после запятой |
| Вложения | Картинки, PDF, текст, CSV, zip и файлы Office, до 20 штук по 20 МБ |

Что проверяет форма: у типа с отметкой **Без родителя** (эпик) родителя нет, а у типа с отметкой **Нужен родитель** (подзадача) он обязателен; родитель из того же проекта; задача не может стать дочерней самой себе или одной из своих подзадач. Автор — администратор, создавший задачу, подставляется сам. Новая задача получает тип, статус и приоритет с отметкой **По умолчанию**, а момент, когда она дошла до статуса категории **Готово**, запоминается как время завершения. **Решение** говорит, почему задачу закрыли (выполнено, не будет сделано, дубликат …); его выбирает человек.

## Комментарии и история

Вкладка **Комментарии и история** показывает сверху вниз, от новых к старым, что сказали и что произошло: комментарии и строку на каждую смену статуса, исполнителя и приоритета — кто и когда. Чтобы написать комментарий, заполните **Новый комментарий** и сохраните задачу. Больше нигде в панели комментарии не добавляются и не правятся, чтобы переписка оставалась такой, какой была.

**Комментарии к задачам** в меню — те же комментарии списком по всем задачам, только для чтения.

## Типы, статусы, приоритеты и решения

Это четыре списка записей, а не код: **Типы задач**, **Статусы**, **Приоритеты** и **Решения** есть в меню модуля, администратор добавляет, переименовывает, упорядочивает и удаляет их строки. Плагины и следующие этапы читают их так же.

| Список | Встроено | Кроме названия |
|---|---|---|
| Статусы | К выполнению, В работе, На проверке, Готово | **Категория** (к выполнению, в работе, готово): статус категории «готово» закрывает задачу, как бы ни назывался |
| Типы задач | Задача, Ошибка, История, Эпик, Подзадача | **Без родителя** (эпик) и **Нужен родитель** (подзадача) |
| Приоритеты | Самый низкий … Самый высокий | **Значок** перед названием (⇣ ↓ → ↑ ⇡), чтобы приоритет различался не только цветом |
| Решения | Выполнено, Не будет сделано, Дубликат, Не воспроизводится | |

Правила всех списков: **код** (строчные буквы, цифры, `_`) выбирается один раз, потому что его хранят задачи; **название** можно оставить пустым — тогда встроенное название показывается на языке каждого администратора, а написанное вами выводится как есть; строка с отметкой **По умолчанию** достаётся новой задаче (без отметки — первая); пока строку используют задачи, её не удалить: сначала поменяйте их.

## Мои задачи и фильтры

Кнопка **Мои задачи** над списком показывает то, что поручено вам и не завершено (`/admin/tracker_tasks?mine=1`). Над списком: проект, статус, исполнитель, тип, метка, **Просроченные** и **Мои**.

## Почта

Письмо на языке самого администратора уходит исполнителю, когда:

- ему поручили задачу (новую или переданную позже);
- у его задачи сменился статус.

Тому, кто сам вносит изменение, о нём не пишут; неактивному администратору тоже. Письмо уходит только после того, как изменение сохранено окончательно. Текст простой, со ссылкой на задачу. Каждый вид можно отключить в настройках.

## Настройки

Экран настроек модуля (`/admin/modules/tracker/settings`):

| Настройка | По умолчанию |
|---|---|
| Отключённые плагины | никакие (поле появляется, когда установлен [плагин](tracker-plugins.ru.md)) |
| Письмо при назначении | включено |
| Письмо при смене статуса | включено |

## Права

У каждого из трёх разделов и каждого из четырёх списков обычные права в форме роли: просмотр, создание, изменение, удаление. Роль, которой разрешён только просмотр, видит списки и задачи и ничего не меняет; **Комментарии к задачам** только для чтения у всех.

## Хуки

Два события для других модулей и сайта:

```php
use Atrium\Admin\Facades\Hook;

Hook::on('atrium.tracker.task.status_changed', function (Task $task, string $from, string $to): void {
    // ...
});

Hook::on('atrium.tracker.task.assigned', function (Task $task, int $assigneeId): void {
    // ...
});
```

## Демо

`php artisan atrium:install --demo` или `atrium:module:install alveby/atrium-tracker --demo` создаёт два проекта (интернет-магазин и сайт компании) и десять задач во всех четырёх статусах: эпик, подзадачи, просроченные, метки и по комментарию. Если в трекере уже есть проект, ничего не делает; писем не шлёт.
