# 1C

[English](1c.md) · [Русский](1c.ru.md)

`alveby/atrium-1c` lets **1C:Enterprise** send its catalogue to the site over the standard **CommerceML 2** exchange, the same one 1C-Bitrix uses. A stock 1C configuration (1C:Trade Management, Accounting, Retail and the like) connects to Atrium **without changes on the 1C side**: in the exchange settings you change only the site address, the login and the password.

- **From 1C to the site:** sections, products, their properties, pictures, prices and stock go into the [catalogue module](../packages/catalog/README.md) (`alveby/atrium-catalog`). Every product and section is matched by its 1C identifier, so the next exchange **updates** what is there and adds what is new: nothing is duplicated. What 1C sends is overwritten on every exchange; fields 1C does not send (SEO, related products and the like) are left as you set them.
- **An exchange screen** in the admin: when, which file, what came, what was skipped, what failed.
- It stands on the [integrations base](integrations.md): every exchange is a line of the exchange log, and the administrators get a letter when an exchange fails.

Orders **to** 1C need the shop module, which is not released yet; they are not part of this module (see [What waits for the shop](#what-waits-for-the-shop)).

## Install

```bash
composer require alveby/atrium-catalog alveby/atrium-integrations alveby/atrium-1c
php artisan atrium:module:install alveby/atrium-catalog
php artisan atrium:module:install alveby/atrium-integrations
php artisan atrium:module:install alveby/atrium-1c
```

The module needs PHP extensions `dom`, `xmlreader` and `zip`. The exchange is run by 1C calling the site, so no queue is needed.

## Set the login and the password

Open **Modules → 1C** and give a **login** and a **password** for the exchange. Make them up for this purpose: they are not the login of an administrator and give no access to the admin. The password is stored **encrypted** and never shown again (the field shows a mask); to change it, type a new one, to keep it, leave the field empty.

Until both are set, the exchange answers every request with «Wrong login or password, or the exchange is not set up in Modules → 1C» and nothing is imported.

The same screen shows the **address of the exchange** to give to 1C. There are two, and both do the same:

| Address | When to use |
|---|---|
| `https://your-site.example/atrium-1c/exchange` | The default |
| `https://your-site.example/bitrix/admin/1c_exchange.php` | For a 1C configuration that is set up for a Bitrix site and that you do not want to touch: only the host changes |

## Set up the exchange in 1C

In 1C open the exchange settings with a site (in 1C:Trade Management: **Administration → Data exchange → Exchange with sites**; in other configurations: **Exchange with 1C-Bitrix** or **Exchange with sites**) and add the site:

1. **Site address:** the address from the previous step.
2. **Login and password:** the ones you set in **Modules → 1C**.
3. Choose the catalogue (the products and groups) to be sent, and the price types and warehouses to take the prices and stock from.
4. Run **Export the catalogue** (the name differs between configurations).

1C does the rest: it logs in, learns the limits, sends the file (`import.xml` for the catalogue and `offers.xml` for prices and stock, often in a zip archive, in parts when it is big) and asks the site to import it. The result is shown in 1C and on the site's exchange screen.

The same setting works for a schedule: 1C can run the exchange by itself every hour.

## What comes from 1C and where it goes

| In 1C | On the site |
|---|---|
| A group of the catalogue | A **section**; a group inside a group is a subsection |
| A product | A **product** of the catalogue, with the name, the article, the description, a section (the first group it is in) |
| A product that is marked as deleted | The product is switched off, not deleted |
| Properties and details | The product's **features**, one line «Name: value» each |
| Pictures | Files in the public storage; the first is the preview and the main picture, all of them are in the gallery. A picture that is not jpg, png, gif or webp is skipped |
| A price | The product's **price**, the first price type in the offer |
| Stock | **In stock** when 1C says there is more than zero; **not in stock** otherwise |

A product and an offer (price and stock) come in two files, and the order does not matter much: if `offers.xml` arrives for a product the site has never seen, that offer is **skipped** and counted on the exchange screen; send the catalogue first.

The identifier is the product's 1C identifier (the part before `#` when an offer is a variant). One product with several offers takes the **last price** and is in stock if **any offer** has goods.

## The exchange screen

**Modules → 1C exchange** lists the runs, newest first: the file, when it started, the result (**In progress**, **Done**, **Failed**), the numbers of new and updated products, updated offers and errors. Open a run to see all the numbers (sections made and updated, products, offers, skipped items) and the first lines of the errors.

A run that came with errors but was not a total failure is **Done** with the error count; the lines are in the [exchange log](integrations.md) too (**Failed** for an exchange that had errors). Delete runs you do not need; nothing else on the site depends on them.

## If something does not arrive

Open **Exchange log** (Modules → Integrations) and filter by `1c`. The usual causes:

| What 1C or the log says | What to do |
|---|---|
| `failure` and «Wrong login or password…» | Check that the login and the password are set in **Modules → 1C** and are the same in 1C. After 20 wrong tries in a minute from one address the site stops answering until the minute is over |
| «The zip archive … cannot be opened» | The file was cut on the way; check the free space and the upload limits of the web server and retry |
| «The file … is not well-formed XML» | 1C sent a file that is not CommerceML (a wrong exchange type in 1C, a proxy that changed the answer) |
| Products arrive without prices | `offers.xml` has not been imported yet, or 1C was told to send no prices |
| Nothing in the log | 1C did not reach the site: check the address, the certificate, and that the site is not behind a password |

## What waits for the shop

The shop module is not released yet, so the second half of the exchange is **not here**: orders from the site to 1C, and their statuses back. When 1C asks for orders (`type=sale`) the site answers that there are none and writes a line in the log, so a 1C configuration that does both exchanges runs without errors. Orders will be added to this module when the shop is released.

The stock is also only «in stock / not in stock» for now: the catalogue has no quantity. It will carry a number with the shop.

## Limits

- The site tells 1C to send files in parts of up to 2 MB; a zip archive is unpacked on the site.
- A big file is imported in steps of 500 items, 1C asks for the next step by itself, so a catalogue of any size does not hit the time limit of the web server.
- Only the catalogue exchange (`type=catalog`) works. The files are kept in the private storage of the site, in the folder `atrium-1c`, until the next exchange.
