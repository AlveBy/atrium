# Импорт и выгрузка

[English](import-export.md) · [Русский](import-export.ru.md)

Любой модуль админки загружает свои записи из CSV и Excel (xlsx) и выгружает свой список в них: новости, страницы, товары, ваш собственный модуль. Каждая строка сохраняется так же, как её сохранила бы форма модуля, — с той же проверкой, своими полями, SEO, языками и хуками. Импорт не может сделать ничего, чего не может форма. Файл, выгруженный из списка, загружается обратно как есть, без правок.

## В админке

**Импорт** — кнопка над списком модуля (Новости → Импорт, Страницы → Импорт, Товары → Импорт):

1. Загрузите файл. Покажутся первые строки и поле для каждой колонки — угаданное по названиям колонок.
2. Поправьте, где угадано не то, выберите, по какому полю искать записи и что с ними делать, и нажмите **Проверить**. Проверка читает весь файл и ничего не записывает.
3. В отчёте видно, сколько записей создастся и обновится, сколько строк пропустится и в каких строках ошибки и почему. Исправьте файл и загрузите заново или поменяйте колонки и проверьте ещё раз.
4. **Импортировать** записывает то, что показала проверка. После — тот же отчёт, уже с настоящими числами.

**Остановить** прерывает проверку или импорт; уже импортированное остаётся. На странице — последние 20 импортов модуля с итогами.

## Выгрузка

**Выгрузка CSV** и **Выгрузка Excel (.xlsx)** рядом с кнопкой импорта скачивают список модуля таким, каким он на экране: поиск и фильтры применены, сортировка сохранена. Страницей выгрузка не ограничена: пишутся все записи, которые находит список.

В файле строка заголовков и по строке на запись: сначала id, потом каждое поле формы в порядке формы, под подписями самой формы. Поле, которое хранится на каждом языке контента, занимает по колонке на язык («Название (English)», «Название (Deutsch)»). Поле-дерево (раздел, категория) пишется путём, несколько значений в ячейке соединяются через `|`, галочка — `1` или `0`, дата — `2026-03-05` или `2026-03-05 14:30:00`.

Загрузите файл обратно — каждая строка найдёт свою запись по id и ничего не изменит. Поправьте перед этим несколько ячеек — и обновятся только эти записи: самый быстрый способ сменить цены или тексты разом.

Текстовая ячейка, которая начинается с `=`, `+`, `-`, `@`, табуляции или возврата каретки (и не является просто числом), пишется с апострофом в начале, чтобы таблица показала её текстом, а не выполнила как формулу; при импорте апостроф снимается обратно.

## Файл

- CSV или xlsx (Excel 2007 и новее; старый `.xls` можно пересохранить в Excel как xlsx или CSV). Из книги читается первый лист.
- В первой строке — названия колонок, в остальных — записи. Пустые строки пропускаются.
- CSV в UTF-8 (с BOM или без) или в windows-1251, через `;`, `,` или табуляцию: и кодировка, и разделитель определяются сами.
- По умолчанию до 50 МБ (`atrium.import.max_size`).

## Колонки

Колонка заполняет любое поле формы модуля, которое принимает текст: название, символьный код, цену, активность, сортировку, даты, значения списков и множественного выбора (по значению или по названию), запись другого модуля (по id или названию), повторяющиеся значения, тексты, картинки и галереи, поля SEO, свои поля и поле-дерево — по названию или пути. Поле, которое хранится на каждом языке контента, занимает по колонке на язык.

Колонка угадывается по подписи поля на любом из 15 языков админки, по ключу поля (`price`, `external_id`) или по привычному синониму, который добавил модуль (`SKU`, `Артикул` у товаров). Колонку, которую угадать не удалось, импорт пропускает, пока ей не выбрать поле. Если файл с такими же колонками уже импортировали, его колонки и настройки предлагаются снова.

Значения:

- **Пустая ячейка оставляет поле как было.** Чтобы не трогать цену, оставьте ячейку пустой — случайно ничего не сотрётся.
- Числа: `1 299,50`, `1,299.50` и `1.299,50` — это 1299,50.
- Да и нет: `1`/`0`, `да`/`нет`, `yes`/`no`, `true`/`false`, `Y`/`N`, `+`/`-`. Галочка, которая хранит своё значение (`YES`), понимает те же слова.
- Даты: `2026-03-05`, `05.03.2026`, `05/03/2026`, со временем, если оно есть у поля (у поля без времени оно отбрасывается); даты Excel читаются как даты.
- Несколько значений в ячейке (множественный выбор, повторяющиеся значения) — через `|` или с новой строки. Галереи — ещё и через запятую, пробел или `;`.

## Как находятся записи

**Искать записи по** — колонка, которая говорит, какая это запись: `id`, символьный код или то, что предлагает модуль (у товаров — артикул, код, внешний код). Запись с тем же значением обновится, которой нет — создастся. Если значение у двух записей одинаковое, обновится та, что заведена раньше. Выгрузка пишет id, поэтому выгруженный файл находит свои записи без всякого выбора.

**Что делать**: создавать новые и обновлять существующие (по умолчанию), только создавать новые (строки уже заведённых записей пропускаются) или только обновлять существующие (строки записей, которых нет, пропускаются — удобно для прайса, который не должен добавлять товары).

Обновление частичное: проверяются и записываются только колонки из файла. Строке, которая создаёт запись, нужно то же, что форме, — хотя бы название.

## Деревья: разделы и категории

Если в форме модуля есть поле-дерево (раздел товара, родитель страницы), оно читается как название в любом месте дерева (`Куртки`) или как путь от верха (`Одежда / Куртки`), регистр не важен. Если название есть у двух элементов, нужен путь — отчёт об этом скажет. Разделитель по умолчанию `/`, его меняет настройка **Разделитель пути**.

Создаются ли недостающие элементы — решает модуль. Каталог предлагает **Создавать разделы, которых нет**: недостающие разделы пути создаются, каждый внутри предыдущего, с символьным кодом из названия, как его делает форма. Без галочки строка с неизвестным разделом попадает в ошибки.

## Картинки

В ячейке картинки или галереи — адреса или пути:

- **Адрес** (`https://…`) скачивается в медиабиблиотеку (в коллекцию с названием «Импорт»), и запись получает сохранённый файл. Один адрес скачивается один раз: повторный импорт того же файла его не качает. Сохраняются только JPEG, PNG, GIF и WebP — по содержимому, а не по расширению; до 10 МБ (`image_max_size`) и 10 секунд (`image_timeout`) на картинку.
- **Путь** берётся, если файл уже лежит на сайте: от корня сайта (`/upload/catalog/1.jpg`) или на диске public (`catalog/1.jpg`). Пути за пределы сайта (`..`, другие схемы) не принимаются.

Скачивается только из интернета. Адрес, имя которого ведёт во внутреннюю сеть (сам сервер, его сеть, метаданные облака, частные и служебные диапазоны), не скачивается, и каждый редирект — не больше трёх — проверяется так же. Файл не заставит сервер постучаться в собственную сеть. Проверка только смотрит, адрес ли это, но ничего не скачивает.

## Проверка и отчёт

Проверка прогоняет каждую строку через ту же валидацию, что и импорт, но ничего не пишет. Запись, которая встречается в файле дважды, считается один раз созданной и один раз обновлённой — как и сделает импорт; элементы дерева, которые будут созданы, тоже посчитаны. Строка попадает в ошибки, если её не приняла бы форма (с сообщениями самой формы), если значения нет среди вариантов поля, если нет элемента дерева или картинки. В отчёте перечислены первые 500 строк с причинами (`errors`), остальные только посчитаны.

Ошибка в строке не останавливает остальные. Ошибка базы данных на строке записывается в журнал, строка уходит в ошибки. Если сломался сам импорт (кончилось место на диске), он останавливается с объяснением; уже импортированное остаётся.

## Большие файлы

Файл читается по 100 строк (`chunk`) с того места, где остановился прошлый шаг, поэтому файлу на 100 000 строк памяти нужно не больше, чем файлу на 100.

- **С обработчиком очереди** (`QUEUE_CONNECTION` не `sync`) импорт двигает задача — до 20 секунд за раз (`seconds`), — и сама ставит в очередь следующий шаг.
- **Без него** импорт двигает страница с ходом импорта — по 5 секунд (`request_seconds`) раз в секунду, пока она открыта, — и планировщик раз в минуту (`atrium:import --pending`, админка ставит его сама; в cron должен быть `php artisan schedule:run`, как требует Laravel).

Над одним импортом в каждый момент работает только кто-то один. Выгрузка читает список порциями по 500 записей (`export.chunk`) и пишет файл по ходу дела.

## Из консоли и по расписанию

```bash
php artisan atrium:import news storage/news.xlsx
php artisan atrium:import catalog_products https://supplier.example/price.csv --key=external_id --mode=update
php artisan atrium:import catalog_products price.csv --like=12 --check
php artisan atrium:export pages storage/pages.csv
php artisan atrium:export news --format=xlsx --search=весна --filter=active=1
```

`atrium:import {модуль} {источник}`: модуль — ключ из адреса в админке (`news`, `pages`, `catalog_products`), источник — файл или адрес (скачивается не дольше двух минут).

- `--like=12` — разложить колонки, как в импорте номер 12 (по названиям колонок), и взять его настройки. Без него колонки угадываются.
- `--map="Цена опт=price"` — колонка и поле, которое она заполняет; для нескольких — повторить. `--map="Комментарий="` — колонку пропустить. Колонка от поля отделяется по последнему `=`.
- `--key=id`, `--key=code`, … — колонка, по которой находятся записи; `--mode=both|create|update`.
- `--option=create_sections=1` — настройка модуля, `имя=значение` (настройка каталога, разделитель дерева `--option=separator=">"` и любая, которую добавит ваш модуль). Неизвестное имя отклоняется.
- `--check` — только проверить и вывести отчёт.

Команда работает до конца и выводит отчёт и каждую строку, которая не импортировалась. Код выхода — 1, если хоть одна строка не прошла или импорт сломался, так что испорченный прайс по расписанию не пройдёт незамеченным:

```php
// routes/console.php
Schedule::command('atrium:import catalog_products https://supplier.example/price.csv --like=12')
    ->dailyAt('06:00')
    ->emailOutputOnFailure('shop@example.com');
```

Импорты из консоли тоже видны в списке в админке, в колонке «Кто» — «консоль».

`atrium:export {модуль} {файл?}` пишет весь список или то, что выберут `--search`, `--filter=имя=значение` (можно повторять) и `--sort`/`--direction`, как в адресе списка. Без файла пишет `{модуль}-{дата}.csv` в текущую папку; формат берётся из расширения файла или из `--format=csv|xlsx`.

## Кто может импортировать и выгружать

Импорт и выгрузка — отдельные права, **Импорт** и **Выгрузка** в строке каждого модуля в форме роли (`news.import`, `news.export`): редактор, которому можно править записи, не загрузит их тысячу и не унесёт весь список, если роль этого не разрешает. Суперадмину можно всегда. Кнопки видят только те, кому можно.

## Для авторов модулей

Модуль импортируется и выгружается сам, по своему `getAdministrationFields()`: кода не нужно. Модель может поучаствовать тремя способами.

**Отказаться.** Модель, которую нельзя импортировать или выгружать, говорит об этом — и её маршруты и кнопки исчезают:

```php
public static function isImportableInAdmin(): bool
{
    return false;
}

public static function isExportableInAdmin(): bool
{
    return false;
}
```

Значения по умолчанию лежат в `InteractsWithAdmin`: импортируется, если записи можно и создавать, и править; выгружается всегда. Встроенные модули «Сайты» и «Языки» только выгружаются.

**Ключи.** Колонки, по которым запись находится снова, по убыванию приоритета (по умолчанию `['id', 'code']`):

```php
public static function getImportKeys(): array
{
    return ['article', 'code', 'external_id', 'id'];
}
```

**Больше в раскладке колонок и настройки.** Два хука, оба получают класс модели:

```php
use Atrium\Admin\Facades\Hook;
use Atrium\Admin\Transfer\ImportOption;

// Колонки раскладки, array<string,Target>: добавить синонимы или заменить колонку.
Hook::filter('atrium.import.targets', static fn (array $targets, string $model): array => $model === Product::class
    ? [...$targets, 'price' => $targets['price']->withSynonyms(['cost', 'цена'])]
    : $targets);

// Настройка страницы импорта, консольного --option и то, что читают колонки.
Hook::filter('atrium.import.options', static fn (array $options, string $model): array => $model === Product::class
    ? [...$options, new ImportOption('create_sections', 'Создавать разделы, которых нет', ImportOption::BOOLEAN, false)]
    : $options);
```

Колонка может и читать ячейку по-своему (`resolve`), и писать её обратно по-своему (`export`). Всё, что свойственно именно товарам, — синонимы, колонку раздела, которая создаёт недостающие разделы, настройку — держит `packages/catalog/src/ProductImport.php` поверх этого механизма.

## Настройки

`php artisan vendor:publish --tag=atrium-config` копирует `config/atrium.php`; ключи — в разделах `import` и `export`:

| Ключ | По умолчанию | |
|---|---|---|
| `import.directory` | `storage/app/private/atrium-imports` | где ждут загруженные файлы, приведённые к CSV в UTF-8; удаляются, когда импорт закончен или остановлен (`ATRIUM_IMPORT_DIRECTORY`) |
| `import.max_size` | `51200` | самый большой файл, КБ |
| `import.chunk` | `100` | сколько строк читать за раз |
| `import.seconds` | `20` | сколько работает шаг задачи очереди или планировщика |
| `import.request_seconds` | `5` | сколько работает шаг страницы с ходом импорта |
| `import.errors` | `500` | сколько строк перечислять в отчёте |
| `import.image_timeout` | `10` | секунд на скачивание картинки |
| `import.image_max_size` | `10240` | самая большая картинка, КБ |
| `export.chunk` | `500` | сколько записей читать из базы за раз |
