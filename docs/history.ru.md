## Журнал изменений

**Журнал изменений** в меню (`/admin/activity`) показывает изменения всех модулей, новые сверху, по 50 на странице. В каждой записи сказано, что произошло (создано, изменено, удалено, восстановлено), с какой записью какого модуля, кто это сделал, откуда (в панели, через API, импортом, командой, по расписанию) и когда, и есть таблица изменённых полей: название поля из формы, что было и что стало. Старое значение зачёркнуто, новое нет, и столбцы называются **Было** и **Стало**, так что они различаются не только цветом. Пока запись существует, на неё ведёт ссылка.

Над списком журнал сужается по модулю, по администратору и по дням (**С** и **По**, оба дня включительно). Фильтры остаются в адресе: суженный журнал можно положить в закладки или отправить.

В форме каждой записи есть кнопка **История**: те же записи журнала, но только про неё.

## Что пишется и откуда

Все сохранения проходят через одно место, поэтому запись в журнале появляется, что бы ни внесло изменение:

| Откуда изменение | Источник в журнале | Кто |
|---|---|---|
| Форма записи в панели | в панели | вошедший администратор |
| `/api/v1` и инструменты MCP | через API | владелец токена |
| Импорт CSV или Excel | импортом | тот, кто запустил импорт |
| Кнопка модуля на записи, массовое действие | в панели / через API | тот, кто нажал, даже если оно выполняется в очереди |
| Консольная команда, своя задача очереди | командой | никто («Система») |

У новой записи перечислены все значения, которые она получила, включая значения по умолчанию из модели. У изменённой — только поля, которые отличаются: сохранение без изменений не оставляет записи, а пустой текст и отсутствие значения считаются одним и тем же. Переводы сравниваются по языкам, поля связей — по выбранным id, пользовательские поля и SEO — так, как их показывает форма. Поля формы только для чтения не сравниваются. Удалённая запись пишется со своим названием, чтобы было понятно, что это было.

Запись журнала пишется в той же транзакции базы, что и сама запись: неудачное сохранение не оставляет следа, а удачное никогда не теряет свою запись в журнале.

Собственная кнопка модуля (`RecordAction`, `BulkAction`) может менять записи как угодно; всё, что она сохраняет через Eloquent, пока работает, попадает в журнал поле за полем — относительно того, что было в базе.

## Пароли и другие секреты

Пароль, ключ или токен никогда не пишутся в журнал, даже в виде хеша. Когда такому полю дают новое значение, в журнале сказано, что поле изменено, — без значения. Поле считается секретным, если это:

- поле ввода пароля (`TextField::make('password')->password()`);
- атрибут, который модель скрывает (`$hidden`, как `password` и `remember_token` у администраторов);
- поле, в имени которого есть одно из слов `atrium.history.secrets` в любом регистре: по умолчанию `password`, `secret`, `token`, `api_key`, `private_key`.

Свои слова добавляются в `config/atrium.php`:

```php
'history' => [
    'enabled' => env('ATRIUM_HISTORY_ENABLED', true),
    'secrets' => ['password', 'secret', 'token', 'api_key', 'private_key', 'passport'],
],
```

## Кто что видит

Журнал показывает записи только тех модулей, которые администратор может смотреть (`{module}.view`); фильтр по модулю перечисляет только их. Кнопке **История** у записи нужно то же право, что и её форме. Если сайтов несколько, в журнале видно то, что сделано на сайте, с которым сейчас работает панель, и в модулях, общих для всех сайтов; история записи другого сайта не находится.

## Как выключить

Для всего сайта: `ATRIUM_HISTORY_ENABLED=false` в `.env`. Ничего не пишется, журнал, его пункт меню и кнопки **История** пропадают. Записанное раньше остаётся в таблице `admin_activity`.

Для одного модуля — в его модели:

```php
public static function hasAdminHistory(): bool
{
    return false;
}
```

Записи модуля не попадают в журнал, и в его форме нет кнопки **История**.

## Авторам модулей

Для сохранения через форму, API, MCP или импорт ничего делать не нужно: запись в журнал пишет ядро. Модуль, который пишет записи по-своему, вне запроса панели, может сделать это явно:

```php
use Atrium\Admin\History\ActivityLog;

$log = app(ActivityLog::class);

// Всё сохранённое внутри попадёт в журнал поле за полем, как от кнопки модуля.
$log->watch(fn () => $order->update(['status' => 'paid']));

// Называет источник и администратора того, что пишется внутри.
$log->during(ActivityLog::SCHEDULE, null, fn () => $this->publishDue());

// Одна запись вручную.
$log->record($order, ActivityLog::UPDATED, ['status' => ['old' => 'new', 'new' => 'paid']]);
```

`ActivityLog::changes($before, $after)` сравнивает два массива значений полей так же, как форма, и возвращает то, что принимает `record()`.
