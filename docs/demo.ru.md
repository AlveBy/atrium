# Публичное демо

Демо Atrium, в которое может войти кто угодно, что-то поменять и сломать, и которое само возвращается в исходное состояние каждый час. Это один контейнер: демо-магазин и примеры сайтов, один администратор и планировщик, который всё сбрасывает.

## Попробовать

Нужен Docker. Из копии этого репозитория:

```bash
docker compose -f docker/demo/compose.yaml up --build
```

Откройте <http://localhost:8000/admin> и войдите как `demo@atrium.test` с паролем `demo`. Сам сайт по адресу <http://localhost:8000>.

Без Compose:

```bash
docker build -f docker/demo/Dockerfile -t atrium-demo .
docker run --rm -p 8000:8000 atrium-demo
```

## Что может и чего не может посетитель

Администратор `demo` не суперадминистратор. Его роль «Demo» создаёт сброс:

- **Правит** содержимое всех модулей: товары, новости, страницы, меню, FAQ, формы, команду, SEO и остальное, с загрузкой файлов (не больше 2 МБ, пять файлов в запросе).
- **Смотрит** администраторов, сайты, языки, проверки доступности и инциденты и ничего в них не меняет. Это разделы из `atrium.demo.read_only`.
- **Не имеет** ролей, API-токенов, экрана кеша, настроек модулей, экрана «Модули» и резервных копий.
- **Не может менять** своё имя, e-mail и пароль: панель отвечает 403.

Код при входе выключен (`ATRIUM_2FA_ENABLED=false`), почта пишется в лог, а пароль учётной записи, которую создаёт установщик до того, как её заменит сброс, не знает никто.

## Сброс

```bash
php artisan atrium:demo:reset
```

Команда удаляет всё из базы и заполняет её демо-содержимым заново, удаляет файлы, которые посетители загрузили на диск `public`, и создаёт администратора `demo` с его ролью. Посетители выходят из системы: сессии лежат в базе.

Без `ATRIUM_DEMO=true` команда не запускается, поэтому на настоящем сайте она ничего не делает. Планировщик запускает её каждый час; `ATRIUM_DEMO_RESET` — выражение cron (`*/30 * * * *` — каждые полчаса). Контейнер сам запускает `schedule:work`; на своём сервере добавьте обычную строку cron `* * * * * php artisan schedule:run`.

| Переменная | По умолчанию | |
|---|---|---|
| `ATRIUM_DEMO` | `false` | Режим демо: сброс работает, профиль заблокирован |
| `ATRIUM_DEMO_EMAIL` | `demo@atrium.test` | Логин посетителя |
| `ATRIUM_DEMO_PASSWORD` | `demo` | Его пароль |
| `ATRIUM_DEMO_RESET` | `0 * * * *` | Когда планировщик сбрасывает демо |
| `ATRIUM_AI_DEMO_DAILY_LIMIT` | `40` | Обращений к ИИ в день на всё демо (`0` — без потолка), см. ниже |
| `ATRIUM_AI_DEMO_STORE` | `file` | Хранилище кэша, в котором лежит этот счётчик |

### ИИ в демо

Если в демо есть модуль ИИ (`alveby/atrium-ai`) и ключ провайдера, помните о бесплатной квоте ключа: все посетители — один администратор, и никто, кроме дневного потолка, не помешает одному из них израсходовать её всю. При `ATRIUM_DEMO=true` модуль считает обращения всего сайта (окно «Сгенерировать», помощник, API и MCP) и при достижении `ATRIUM_AI_DEMO_DAILY_LIMIT` пишет в окне, что дневной лимит исчерпан, а API отвечает 429, не обращаясь к провайдеру. Счётчик лежит в хранилище кэша `file`, потому что почасовой сброс очищает базу (а с ней и кэш `database`). Окно и помощник также напоминают посетителям, что демо публичное и персональные данные вводить нельзя. См. [ai.ru.md](ai.ru.md).

## Выставить в интернет

Compose-файл слушает только `127.0.0.1:8000`. Поставьте перед ним обратный прокси с HTTPS, например Caddy:

```
demo.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

и задайте `APP_URL=https://demo.example.com` (в окружении compose-файла). Дальше:

- Контейнер отбрасывает все capabilities, не может получить новые и ограничен 512 МБ памяти, одним процессором и 128 процессами. База — файл SQLite внутри него, так что резервировать и терять нечего.
- Держите демо на отдельном сервере или одноразовом VPS: в демо посторонние могут записывать файлы и гонять код приложения.
- Из контейнера есть выход в интернет. Если он не нужен, дайте контейнеру внутреннюю сеть и пропустите только прокси.
- Ограничьте частоту входов и загрузок в прокси.

## Где разместить

| | Цена | Сброс | Безопасность |
|---|---|---|---|
| Небольшой свой VPS (Hetzner, DigitalOcean, любой) с Docker и Caddy | несколько евро в месяц | планировщик в контейнере | на сервере нет ничего другого; лучший вариант для долгого демо |
| Уже имеющийся сервер | бесплатно | так же | демо делит машину с вашими сайтами: используйте лимиты compose и отдельного пользователя |
| GitHub Codespaces (кнопка «попробовать») | бесплатный лимит на аккаунт, платит сам посетитель | у каждого Codespace своя копия, она исчезает | ничего вашего не открыто; нужен аккаунт GitHub, публичной ссылки нет |
| `docker run` на машине посетителя | бесплатно | каждый запуск новый | ничего не открыто; нужен Docker |
| Бесплатный хостинг контейнеров (Render, Fly.io и подобные) | бесплатные тарифы меняются и засыпают без трафика | планировщик не работает во сне, зато контейнер стартует заново | нормально, но первый заход медленный |

Для ссылки, которую может открыть кто угодно, проще всего VPS с этим compose-файлом.
