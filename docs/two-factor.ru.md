# Двухфакторный вход

[English](two-factor.md) · [Русский](two-factor.ru.md)

`alveby/atrium-2fa` добавляет второй шаг входа в панель и в личный кабинет, а ещё входы без пароля. Каждый guard (`admin`, `account` или ваш собственный) настраивается отдельно.

## Установка

```bash
composer require alveby/atrium-2fa
php artisan atrium:module:install alveby/atrium-2fa
```

Команда создаёт таблицы и включает модуль. До этого пакет ничего не делает: ни маршрутов, ни кнопок, ни второго шага вообще. Код на почту, который раньше был в панели (`ATRIUM_2FA_ENABLED`), теперь живёт в этом пакете — чтобы сохранить его, установите пакет. `atrium:module:remove alveby/atrium-2fa` снова выключает модуль.

Значения по умолчанию лежат в `config/atrium-2fa.php` (`php artisan vendor:publish --tag=atrium-2fa-config`). Большую часть можно менять в панели, в **Модули → Двухфакторный вход**, без выкладки. Пустое поле там оставляет значение из конфига.

## Что видят люди

| Страница | Панель | Кабинет |
|---|---|---|
| Второй шаг после пароля | `/admin/auth/challenge` | `/account/auth/challenge` |
| Свои факторы, коды восстановления, устройства | `/admin/auth/security` | `/account/auth/security` |
| Вход по коду на почту | `/admin/auth/code` | `/account/auth/code` |
| Вход по ключу доступа | `/admin/auth/passkey` | `/account/auth/passkey` |
| Журнал входов | `/admin/auth/log` | — |
| Люди и сброс | `/admin/auth/people` | — |

Страницы кабинета есть и для каждого языка контента (`/de/account/auth/security`). В меню панели появляется группа **Безопасность**: «Моя безопасность» для всех, журнал и люди — для тех, кому можно настраивать модуль (право `two_factor.settings`).

Экран входа показывает только те способы, что включены для guard. Если ничего дополнительно не включено, остаётся обычная форма с почтой и паролем.

## Кому нужен второй шаг

`guards.<guard>.required`, в панели — «Второй шаг для …»:

| Значение | Что значит |
|---|---|
| `all` | Всем. У кого фактора ещё нет, настраивает его сразу после входа, раньше всего остального. |
| `roles` | Суперадминам и ролям из `required_roles` (только панель). Остальные могут включить фактор сами. |
| `optional` | Только тем, кто сам настроил фактор. |
| `null` | Только для админки: старый переключатель `ATRIUM_2FA_ENABLED`. `true` — это `all`, `false` — `optional` и вдобавок убирает код на почту из факторов панели (раньше этот переключатель выключал именно его). |

`factors` перечисляет факторы, доступные людям этого guard. Фактор, убранный из списка, сразу перестаёт работать, в том числе у тех, у кого он был.

## Факторы

**Приложение-аутентификатор (TOTP, RFC 6238).** Любое приложение, читающее QR-код: Google Authenticator, Microsoft Authenticator, 1Password, Aegis, FreeOTP. На странице есть QR-код и ключ текстом — для телефона без камеры. `totp.window` (по умолчанию 1) принимает код на один 30-секундный шаг раньше или позже. Код, которым уже вошли, второй раз не примется.

**Ключ доступа (passkey, WebAuthn).** Touch ID, Windows Hello, телефон или аппаратный ключ. Каждому ключу человек даёт имя, чтобы потом их различать. `webauthn.rp_id` (`ATRIUM_WEBAUTHN_RP_ID`) по умолчанию — домен сайта. Укажите родительский домен, чтобы ключи работали на поддоменах. Ключам нужен HTTPS (или `localhost`).

**Код на почту.** Шесть цифр на адрес учётной записи. Это прежний код на почту из панели, переведённый на тот же контракт, что и остальные факторы.

**Код по SMS.** Шесть цифр на телефон, который человек сначала подтверждает. Из коробки сообщения пишутся в лог; см. [SMS-провайдеры](#sms-провайдеры).

Факторов может быть несколько, на втором шаге человек выбирает любой. Последний фактор удалить нельзя, пока второй шаг для человека обязателен.

## Вход без пароля

Оба способа включаются для каждого guard (`magic_code`, `passwordless`). По умолчанию в кабинете они включены, в панели выключены.

**Код на почту.** Человек вводит адрес и получает шесть цифр. Код живёт `codes.ttl` минут (10), срабатывает один раз и пропадает после `codes.max_attempts` ошибок (5). Новый код можно запросить через `codes.resend_after` секунд (60). Ответ одинаков, есть такой адрес или нет, и приходит за одинаковое время, так что выяснить, у кого есть учётная запись, нельзя. Письмо уходит после ответа.

Код на почту — один фактор. Если человеку нужен второй шаг, он всё равно будет, но почту там второй раз не предложат.

**Только ключ доступа.** Ключ — это уже два фактора (устройство плюс отпечаток или PIN), поэтому он впускает без пароля и без второго шага. Браузер сам предлагает ключи, которые знает для сайта.

## Коды восстановления и доверенные устройства

При настройке первого фактора человек получает `recovery_codes` кодов (10). Они показываются один раз, на странице безопасности; их записывают или кладут в менеджер паролей. Хранятся только хеши. Каждый код один раз заменяет фактор. «Новые коды» на странице безопасности заменяют все.

«Доверять этому устройству» на втором шаге пропускает шаг в этом браузере на `trusted_days` дней (30; при 0 галочки нет). Страница безопасности одной кнопкой забывает все доверенные устройства; сброс админом тоже их забывает.

## Лимиты и блокировка

`limits.per_minute` ошибок в минуту (5) на человека и адрес, потом ожидание. `limits.lockout_after` ошибок подряд (10) блокируют второй шаг на `limits.lockout_minutes` минут (15). Блокировка попадает в журнал.

## Журнал входов и сброс

Журнал хранит по всем guard: входы (и каким способом), запросы второго шага, ошибки, блокировки, отправленные коды, добавленные и удалённые факторы, использованные и обновлённые коды восстановления, доверенные устройства, привязку и отвязку соцсетей (с `alveby/atrium-social-login`) и сбросы. Пишутся IP-адрес и браузер; есть фильтр по guard, событию и человеку.

**Люди** — список людей guard с их факторами. **Сброс** убирает все факторы, коды восстановления и доверенные устройства человека, потерявшего телефон. Человек снова входит по паролю и, где это обязательно, заново настраивает фактор. Сброс попадает в журнал с именем админа, который его сделал.

## SMS-провайдеры

Драйвер — один класс:

```php
use Atrium\TwoFactor\Contracts\SmsDriver;
use Illuminate\Support\Facades\Http;

final class MySmsDriver implements SmsDriver
{
    public function send(string $phone, string $message): void
    {
        Http::withToken(config('services.my_sms.token'))
            ->post('https://sms.example.test/send', ['to' => $phone, 'text' => $message])
            ->throw();
    }
}
```

```php
// config/atrium-2fa.php
'sms' => ['driver' => App\Sms\MySmsDriver::class],
```

Если провайдер отказал — бросайте исключение: человеку скажут, что SMS не ушло, а ошибка попадёт в лог. Токен держите в `.env`, не в коде.

## Свой guard

Добавьте guard в `config/auth.php`, потом в `guards` в `config/atrium-2fa.php`:

```php
'members' => [
    'enabled' => true,
    'prefix' => 'members/auth',
    'middleware' => ['web'],
    'localized' => false,
    'auth_middleware' => 'auth:members',
    'layout' => 'atrium-2fa::layouts.site',
    'login_route' => 'members.login',
    'active_column' => 'active',
    'required' => 'optional',
    'factors' => ['totp', 'passkey'],
    'passwordless' => true,
    'magic_code' => false,
    'trusted_days' => 0,
],
```

Ваш контроллер входа не логинит человека сам, а передаёт его второму шагу:

```php
return app(\Atrium\Admin\Auth\SignIn::class)->start($request, $user, 'members', 'password', $remember);
```

и спрашивает дополнительные кнопки для экрана входа:

```php
$methods = \Atrium\Admin\Facades\Hook::apply('atrium.auth.methods', [], 'members');
// [['key' => 'passkey', 'label' => '…', 'url' => '…', 'icon' => '<svg…>', 'kind' => 'link'], …]
```

## Для других пакетов

| Хук | Вид | Аргументы |
|---|---|---|
| `atrium.auth.methods` | фильтр | способы, guard. Добавить кнопку на экран входа. |
| `atrium.auth.signed_in` | событие | человек, guard, способ (`password`, `passkey`, `code`, `social:github`…). |
| `atrium.auth.event` | событие | guard, человек, событие, способ, подробности. Пишет строку в журнал. |
| `atrium.auth.other_ways_in` | фильтр | число, человек, guard. Сколько у человека способов войти, кроме удаляемого. |

`alveby/atrium-social-login` пользуется всеми четырьмя: кнопки соцсетей на экране входа, входы через соцсети в журнале, и не даёт отвязать последний способ войти.

## Как хранятся секреты

Ключи TOTP, телефоны и данные ключей доступа шифруются ключом приложения (`APP_KEY`, AES-256 с MAC) и привязаны к своей таблице и колонке. Значение, скопированное в другую колонку, не расшифруется. Коды восстановления и коды на почту хранятся только хешами. После смены `APP_KEY` всем придётся заново настроить TOTP и SMS (чтобы этого избежать, используйте `APP_PREVIOUS_KEYS`).

## Контраст

Каждый цвет страниц берётся из темы панели (`--atrium-*`), затем из темы сайта (`--bg`, `--text`…), затем из запасного значения. Ничего не передаётся одним цветом: у ошибки есть полоса, знак «!» и слова; у успеха — «✓»; выбранный фактор выделен жирным, толстой рамкой и `aria-current`; ссылки подчёркнуты.

Коэффициенты контраста по WCAG 2.2. Уровень AA требует 4,5 для текста и 3 для рамок и обводки фокуса.

| Тема | Текст | Подсказки | Текст на кнопке | Рамка поля | Обводка фокуса | Текст ошибки | Знак успеха |
|---|---|---|---|---|---|---|---|
| graphite | 17,7 | 7,6 | 5,2 | 3,7 | 5,2 | 5,7 | 5,0 |
| day | 17,9 | 7,6 | 6,3 | 3,2 | 6,3 | 5,7 | 5,0 |
| night | 14,0 | 7,2 | 9,3 | 3,2 | 8,1 | 7,5 | 9,0 |
| sand | 17,3 | 7,6 | 5,9 | 3,5 | 5,9 | 6,6 | 5,1 |
| contrast | 21,0 | 15,1 | 10,6 | 21,0 | 10,6 | 7,3 | 6,7 |
| сайт, запасные | 17,8 | 7,4 | 6,7 | 4,8 | 6,7 | 17,8 | 17,8 |

Измерено относительно фона карточки. На сайте без темы ошибки и успех окрашены цветом текста и опираются на полосу и знак. QR-код всегда чёрный на белом (21,0) в любой теме, чтобы его прочитал любой телефон.

Страницы входа через соцсети (`alveby/atrium-social-login`) используют ту же палитру. На кнопках провайдеров написано название словами — не только логотип и не только фирменный цвет.
