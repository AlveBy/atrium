# CDN

[English](cdn.md) · [Русский](cdn.ru.md)

CDN хранит копии картинок и файлов сайта на серверах рядом с посетителями. Atrium может поставить его перед всем, на что он ссылается: загрузками, файлами, перенесёнными из 1С-Битрикс, картинками внутри текстов, изображениями темы и, если хотите, собранными скриптами и стилями. Пока вы не зададите адрес, CDN выключен.

## Включение

Создайте в своём CDN (Cloudflare, BunnyCDN, CloudFront и подобных) pull zone, где источником будет сам сайт, а затем:

```bash
ATRIUM_CDN_URL=https://cdn.example.com
php artisan config:cache
```

Теперь каждый адрес, который Atrium строит для пути под `/storage/` или `/upload/`, ведёт на CDN: поля с картинками и галереи, ссылки на файлы, картинка для Open Graph, миниатюры в списках админки и `src`/`href` внутри текстов, написанных в редакторе. Значения в базе не меняются, поэтому выключить CDN обратно — значит просто убрать строку. Другие пути задаются в `config/atrium.php` → `cdn.paths`.

Если Cloudflare стоит перед всем сайтом (DNS через прокси), укажите в `ATRIUM_CDN_URL` собственный адрес сайта, `https://example.com`: файлы останутся на месте и получат адреса с версией, а изменение размера и сброс кеша, о которых ниже, будут работать на них.

## Уменьшенные картинки и WebP/AVIF

Без этого список карточек грузит каждую картинку в полном размере. С драйвером картинок тема просит каждую картинку той ширины, в какой она показана, и даёт браузеру `srcset` на выбор; копию делает и хранит CDN.

| `ATRIUM_CDN_IMAGES` | Что использует | Что ещё задать |
|---|---|---|
| `cloudflare` | [Image transformations](https://developers.cloudflare.com/images/transform-images/) в вашей зоне: `/cdn-cgi/image/width=640,quality=82,format=auto/…` | Включить transformations для зоны |
| `bunny` | [Bunny Optimizer](https://bunny.net/optimizer/): `?width=640&quality=82` | Включить Optimizer для pull zone; WebP/AVIF зависят от его настроек |
| `imgproxy` | Ваш собственный сервер [imgproxy](https://imgproxy.net/) | `ATRIUM_CDN_IMAGES_URL`, а если он проверяет подписи (а он должен), ещё `ATRIUM_IMGPROXY_KEY`/`ATRIUM_IMGPROXY_SALT` |
| `template` | Любой другой сервис, по шаблону адреса | `ATRIUM_CDN_IMAGES_TEMPLATE`, с `{url}` `{path}` `{width}` `{format}` `{quality}` |

`ATRIUM_CDN_IMAGES_FORMAT` — это `auto` (CDN отдаёт AVIF или WebP браузерам, которые их понимают), `webp` или `avif`; `ATRIUM_CDN_IMAGES_QUALITY` — 82. Ширина округляется вверх до 320, 640, 960, 1280 или 1920 пикселей, поэтому у CDN хранится несколько копий каждой картинки, а не по копии на каждую вёрстку (`cdn.images.widths`).

Например, шаблон для сервиса, который принимает `https://img.example.com/640x/storage/a.jpg`:

```bash
ATRIUM_CDN_IMAGES=template
ATRIUM_CDN_IMAGES_TEMPLATE=https://img.example.com/{width}x/{path}
```

Cloudflare и Bunny меняют размер только у картинок, которые проходят через них, поэтому остальные адреса (бакет на другом хосте) остаются как есть. imgproxy и шаблоны забирают любой адрес.

В собственных Blade-шаблонах:

```blade
@php($src = \Atrium\Admin\Support\MediaUrl::to($record->preview_picture))
<img src="{{ \Atrium\Admin\Support\MediaUrl::to($record->preview_picture, 640) }}"
     srcset="{{ \Atrium\Admin\Support\Cdn::srcset($src) }}" sizes="(min-width: 64rem) 20rem, 100vw" alt="">
```

`MediaUrl::to($value, $width)` принимает сохранённое значение любого вида и возвращает адрес через CDN; `Cdn::srcset()` равен null, пока драйвер картинок не задан, и тогда Blade оставляет атрибут пустым.

## Новые версии и удалённые файлы

CDN держит копию, пока та не истечёт, поэтому картинка, заменённая под тем же именем, осталась бы у посетителей старой. Atrium добавляет `?v=` со временем изменения файла к каждому локальному файлу, на который ссылается (`ATRIUM_CDN_VERSION`, по умолчанию включено): изменённый файл получает новый адрес, и CDN забирает его заново. Файлы, загруженные в админке, и так получают новые имена.

У удалённого файла нового адреса нет, поэтому CDN продолжает его отдавать. С драйвером сброса кеша удаление файла в медиабиблиотеке админки убирает его из кеша CDN сразу после ответа страницы (`ATRIUM_CDN_PURGE_ON_DELETE`, по умолчанию включено):

| `ATRIUM_CDN_PURGE` | `.env` |
|---|---|
| `cloudflare` | `CLOUDFLARE_ZONE_ID` и `CLOUDFLARE_API_TOKEN`: токен с правом «Zone → Cache Purge → Purge» только для этой зоны |
| `bunny` | `BUNNY_API_KEY` (Account settings → API) и `BUNNY_PULL_ZONE_ID` для сброса всего кеша |

Токен создайте в панели CDN сами и храните только в `.env`. Вручную, для отдельных файлов или для всего сразу:

```bash
php artisan atrium:cdn:purge /storage/uploads/2026/11/photo.jpg /upload/iblock/1/a.jpg
php artisan atrium:cdn:purge --all
```

Отказ в сбросе пишется в лог; с сайта файл в любом случае исчезает.

## Загрузки в S3

Загрузки можно отправлять в бакет вместо сервера: объявите диск `s3` в `config/filesystems.php` (Amazon S3, Cloudflare R2, Backblaze B2, MinIO…), укажите в `AWS_URL` CDN, стоящий перед бакетом, и направьте на него админку:

```bash
composer require league/flysystem-aws-s3-v3
ATRIUM_UPLOADS_DISK=s3
AWS_BUCKET=site-media
AWS_URL=https://media.example.com
```

Файл, загруженный в админке, сохраняется своим полным адресом на этом хосте, `https://media.example.com/uploads/2026/11/…jpg`, поэтому работает везде, где значение показывается. Копия WebP рядом с ним не создаётся (на локальном диске её делает веб-сервер): вместо этого используйте драйвер картинок с `format=auto`. Удаление в медиабиблиотеке удаляет объект и сбрасывает кеш для этого адреса.

Раз адрес лежит в базе, перенос бакета под другой хост потом означает замену старого хоста во всех сохранённых значениях. Выберите хост CDN до первой загрузки.

## Скрипты и стили

Собственный бандл админки и Vite-сборка вашего сайта тоже могут отдаваться с CDN:

```bash
ATRIUM_CDN_ASSETS=true
```

Браузеры грузят модульные скрипты и шрифты с другого хоста только через CORS, поэтому CDN должен отвечать заголовком `Access-Control-Allow-Origin` для вашего сайта (в Cloudflare и Bunny — правилом заголовка ответа). У собранных файлов имена с хешем, и сброс кеша им не нужен.

## Что ещё важно знать

- У загруженных картинок есть копия в WebP, и веб-сервер отдаёт её браузерам, которые просят WebP, с `Vary: Accept`. Бесплатные тарифы Cloudflare игнорируют `Vary` для картинок и могут закешировать один формат для всех: либо используйте `ATRIUM_CDN_IMAGES=cloudflare` с `format=auto`, либо выключите копии WebP (`ATRIUM_UPLOADS_WEBP=false`).
- В админке миниатюры в списках идут через CDN, как картинки сайта; превью в форме записи берутся с самого сайта, поэтому редактор видит то, что лежит на сервере.
- Текст, написанный как обычный (не HTML), остаётся как есть: в нём нет атрибутов `src`.
