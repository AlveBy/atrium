# Свои поля

[English](custom-fields.md) · [Русский](custom-fields.ru.md)

`alveby/atrium-custom-fields` даёт редактору добавить поле в любой модуль прямо из админки, без миграции и без строчки кода: цвет и размеры у товара, «Сезон» у тура, подзаголовок у новости. Поле появляется в форме модуля, в списке, в API и в инструментах MCP, а помеченные «Фильтр» тянут панель фильтров магазина со счётчиками на 100 000 товаров.

## Установка

```bash
composer require alveby/atrium-custom-fields
php artisan atrium:module:install alveby/atrium-custom-fields
```

Появятся две таблицы, `custom_fields` (описания полей) и `custom_field_index` (индекс для фильтров), а в списке каждого модуля — кнопка **Поля**.

С `--demo` (или `atrium:install --demo`) и установленным каталогом у демо-товаров появятся пять полей с фильтром: вес, время работы от батареи, защита от воды, подключение и гарантия. Названия и варианты написаны на каждом языке интерфейса (`resources/demo/{locale}/fields.php`), а основной язык магазина (`APP_LOCALE`) выбирает единицы: фунты для английского, то есть магазина в США, килограммы для всех остальных. Язык без демо-текстов получает английские.

## Новое поле

В списке модуля нажмите **Поля**, затем **Добавить поле**. У поля есть:

| | |
|---|---|
| Название | Подпись в форме и в списке, на каждом языке контента |
| Код | Латиница, цифры и `_`: имя в API, в фильтрах и в шаблонах. Не может совпадать с колонкой таблицы модуля или с его собственным полем |
| Тип | См. [Типы](#типы). Модуль, код и тип после создания не меняются |
| Модуль привязки | Для привязки: записи какого модуля в ней выбирают |
| Подсказка | Текст под полем в форме |
| Варианты | Для списка: по варианту в строке, `значение = Подпись` или просто подпись |
| Вкладка | Вкладка формы модуля, на которой оно стоит: своя у формы или добавленная вами (см. [Вкладки](#вкладки)) |
| Обязательное, Показывать в списке | |
| Фильтр | Значения копируются в индекс: фильтры, счётчики фасетов, диапазоны |
| Сортировка | Список и API сортируются по нему |
| Поиск | Поиск по списку заглядывает в него (строки и тексты) |
| Переводимое | Своё значение на каждом языке контента (строки и тексты) |
| Своё для каждого сайта | Цена или остаток, которые на сайтах разные |
| Сайт | Показывать поле только на одном сайте |

С первым полем в таблице модуля появляется JSON-колонка `custom`. Модуль может добавить её и сам, в своей миграции:

```php
$table->json('custom')->nullable();
```

## Вкладки

Вкладки, которые есть у модуля, не всегда подходят для группы полей. В списке модуля нажмите **Вкладки**, затем **Добавить вкладку**:

| | |
|---|---|
| Название | Заголовок вкладки, на каждом языке контента |
| Код | Латиница, цифры и `_`: по нему поле называет свою вкладку. Не может совпадать с кодом вкладки, которая у формы уже есть (`seo`, `params`…). Модуль и код после создания не меняются |
| Сортировка | Место вкладки среди вкладок формы: чем меньше число, тем ближе к началу. Если у вкладок формы нет собственных чисел, их нумеруют 0, 10, 20 … в том порядке, как форма их перечисляет, так что 15 поставит вкладку после второй; 500 по умолчанию — в конец |
| Сайт | Показывать вкладку только на одном сайте |

Потом выберите её в поле **Вкладка** у нужных полей. Остальное происходит само:

- вкладка рисуется в форме записи модуля на своём месте и только пока на ней есть поля: вкладка, на которую никто не поставил поле, не показывается;
- **переименовать** вкладку (или поменять сортировку) — значит просто изменить её, поля остаются на ней;
- **удалить** вкладку — поля переедут на вкладку по умолчанию (`params`), ничего не пропадёт, значения останутся в записях; вкладка другого модуля с таким же кодом не затрагивается;
- поле на вкладке, которой у формы на этом сайте нет (вкладка другого сайта), показывается на первой вкладке формы;
- у модуля, в форме которого **вкладок нет совсем**, они появляются вместе с первой добавленной: его собственные поля остаются вместе на первой вкладке «Основное», добавленные идут следом. Пока нет добавленной вкладки с полем, форма остаётся как была, плоской. Так работает любой модуль: другой модуль может добавлять вкладки так же, через хук `atrium.module.tabs`.

Сидеры и код могут создавать вкладки строками, как и поля: `CustomFieldTab::query()->create(['module' => (new Product)->getMorphClass(), 'code' => 'delivery', 'label' => ['en' => 'Delivery', 'ru' => 'Доставка'], 'sort' => 15])`. Кто может открыть экран, решает роль: `custom_field_tabs.view`, `.create`, `.update`, `.delete`, отдельно от `custom_fields.*` у полей.

| Тип | Значение | В индексе |
|---|---|---|
| `string` | Строка до 255 символов | текст |
| `text` | Несколько строк | — |
| `number` | Целое число | число |
| `decimal` | Число с дробью | число |
| `boolean` | Да или нет | число (0/1) |
| `date` | `ГГГГ-ММ-ДД` | дата |
| `select` | Один вариант | текст |
| `multiselect` | Несколько вариантов | текст, строка на вариант |
| `link` | id записи другого модуля | число |
| `file`, `image` | Адрес файла | — |

## Где лежат значения

Запись держит значения в своей колонке `custom`:

```json
{"color": "red", "sizes": ["s", "m"], "subtitle": {"en": "Crunchy", "de": "Knackig"}, "stock": {"1": 5, "2": 0}}
```

Переводимое значение — объект по языкам, значение «для каждого сайта» — объект по id сайта. Чтобы прочитать колонку, не нужен join, а модуль без полей не платит ничего.

Для фильтров и сортировки значения полей с галочками «Фильтр» и «Сортировка» лежат ещё и в `custom_field_index`, по строке на значение: `entity_type`, `entity_id`, `field_id`, `site_id`, `locale` и одна из `value_num`, `value_str`, `value_date`, с индексами по `(field_id, site_id, locale, значение, entity_id)`. Индекс обновляется при каждом сохранении и удалении записи, откуда бы её ни сохраняли (админка, API, сидер, импорт), и пересобирается командой:

```bash
php artisan atrium:custom-fields:reindex
php artisan atrium:custom-fields:reindex "Atrium\Catalog\Models\Product" --field=color
```

Если поставить «Фильтр» уже существующему полю, его строки в индексе заполнит задача в очереди.

## Чтение и запись в коде

```php
use Atrium\CustomFields\CustomFields;

$fields = app(CustomFields::class);

$fields->get($product, 'color');              // на текущем сайте и языке
$fields->get($product, 'subtitle', 'de');     // без перевода — текст языка по умолчанию
$fields->set($product, 'color', 'blue');
$product->save();
```

Или трейтом в модели:

```php
use Atrium\CustomFields\Concerns\HasCustomFields;

class Product extends Model
{
    use HasCustomFields;
}

$product->custom('color');
$product->setCustom('color', 'blue')->save();
```

В шаблоне Blade: `{{ $product->custom('color') }}`, а для модели без трейта — `app(CustomFields::class)->get($product, 'color')`.

## Фильтры, сортировка и фасеты

```php
Product::query()
    ->where('active', true)
    ->whereCustom('color', 'red')                    // =, или любое из списка
    ->whereCustom('weight', '<=', 5)                 // =, !=, <, <=, >, >=, like
    ->whereCustomBetween('price', 10, 50)
    ->orderByCustom('rating', 'desc')                // записи без значения — в конце
    ->paginate(24);
```

Панель фильтров присылает всё разом, в одном виде:

```php
$filters = $request->input('filter', []);
// ['color' => ['red', 'blue'], 'sizes' => ['m'], 'price' => ['min' => 10, 'max' => 50]]

$products = Product::query()->where('active', true)->whereCustomFilters($filters)->paginate(24);

$facets = CustomFacets::for(Product::class, Product::query()->where('active', true))->filters($filters);

$facets->counts(['color', 'sizes']);
// ['color' => ['red' => 120, 'blue' => 75, ...], 'sizes' => ['m' => 80, ...]]
$facets->ranges(['price']);
// ['price' => ['min' => 9.9, 'max' => 120.0]]
```

Каждое поле считается со всеми фильтрами, кроме своего: пока отмечен «Красный», у «Синего» остаётся его число. Фильтр — это `id IN (SELECT entity_id FROM custom_field_index WHERE …)`, счётчик — один `GROUP BY` по индексу, на любой базе.

Фильтр по полю, у которого нет ни галочки «Фильтр», ни своей колонки, бросает `LogicException` с объяснением: перебирать JSON на каждом запросе — ровно то, от чего спасает индекс.

## Горячие поля: настоящая колонка

Поля, которые читаются на каждой странице большого каталога (цена, остаток), можно перенести в настоящую колонку таблицы модуля с индексом:

```bash
php artisan atrium:custom-fields:promote "Atrium\Catalog\Models\Product" price
```

Команда добавит колонку с индексом, перенесёт в неё значения из JSON и уберёт строки поля из индекса. `whereCustom()`, `orderByCustom()`, фасеты, форма, список и API продолжают работать — уже с колонкой, а ещё её можно использовать как обычную (`->where('price', '<', 50)`). Переводимое поле, поле «для каждого сайта» и поле со списком значений остаются в JSON.

## Языки и сайты

Переводимое поле редактируется переключателем языка в форме, как собственные поля модуля. В индексе по строке на каждый язык контента; где перевода нет, берётся текст языка по умолчанию, так что фильтр на немецкой странице находит то, что эта страница показывает.

У поля «для каждого сайта» значение на каждом сайте своё, фильтры и фасеты смотрят на значение текущего сайта. Поле, привязанное к одному сайту, видно только в формах и списках этого сайта.

## API и MCP

Свои поля — обычные поля модуля: `POST /api/v1/catalog_products` и `PATCH` их принимают, ответы их возвращают, `GET /api/v1/catalog_products?filter[color]=red,blue&filter[price][min]=10&sort=rating&direction=desc` фильтрует и сортирует по ним, `search=` ищет в полях с галочкой «Поиск». Они есть в документации API (`/api/v1`, `openapi.json`) и в инструменте MCP `describe_module`, так что ИИ-помощник заполняет их, как любые другие.

## Скорость

Панель фильтров на 100 000 товаров (четыре поля: цвет из десяти, один-два размера из пяти, вес и рейтинг), медиана семи прогонов на ноутбуке (Apple M-series, PHP 8.4, базы в Docker):

| | Найдено товаров | Отфильтрованный список, страница из 24 по рейтингу | Фасеты: 2 счётчика и 1 диапазон | Пересборка индекса |
|---|---|---|---|---|
| MySQL 8.4 | 2 565 | 185 мс | 374 мс | 13,2 с |
| PostgreSQL 17 | 2 565 | 98 мс | 210 мс | 10,4 с |
| SQLite | 2 565 | 54 мс | 76 мс | 4,3 с |

Повторить у себя:

```bash
CUSTOM_FIELDS_BENCHMARK=100000 vendor/bin/phpunit packages/custom-fields/tests/Benchmark
```

с `DB_CONNECTION=mysql` или `pgsql` и настройками `DB_*` этой базы.

После пересборки индекса тест выполняет `ANALYZE`, как база делает сама через несколько секунд после массового изменения. Сразу после `atrium:custom-fields:reindex` большого модуля MySQL может понадобиться эти несколько секунд (или `ANALYZE TABLE custom_field_index`), чтобы фильтры работали так же быстро. SQLite статистику не ведёт, и здесь она ей не нужна.

## Полнотекстовый поиск через Scout

Индекс — для точных фильтров, диапазонов и счётчиков. Для поиска с опечатками по многим полям подключите [Laravel Scout](https://laravel.com/docs/scout) с Meilisearch или Typesense и положите значения в документ поиска:

```php
use Atrium\CustomFields\CustomFields;
use Laravel\Scout\Searchable;

class Product extends Model
{
    use Searchable;

    public function toSearchableArray(): array
    {
        $fields = app(CustomFields::class);

        return [
            'id' => $this->id,
            'name' => $this->name,
            ...collect($fields->fields($this))
                ->mapWithKeys(fn ($field) => [$field->code => $fields->value($this, $field)])
                ->all(),
        ];
    }
}
```

Перечислите коды полей с «Фильтром» в настройках индекса движка как filterable attributes и пишите `Product::search('хрустящий')->where('color', 'red')`. Scout переиндексирует запись при сохранении, так что свои поля едут вместе с ней.
