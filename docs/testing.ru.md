## Перед каждым пушем

```bash
vendor/bin/pint && php scripts/copyright-header.php --fix
bin/ci --changed
```

`bin/ci` — то же, что запускает GitHub Actions, только на вашей машине. Запускайте его перед каждым пушем: то, что он не пропустил, не должно попасть в main. С `--changed` он проверяет только пакеты, которые может сломать ваше изменение: сам пакет и все, что от него зависят, — поэтому изменение админки запускает все. Это удобно в работе; CI проверяет все пакеты.

| Шаг | Что делает |
|---|---|
| `lint` | Pint и заголовок с копирайтом в каждом файле |
| `static` | PHPStan |
| `tests` | PHPUnit каждого пакета в своём процессе, параллельно, на SQLite, MySQL и PostgreSQL |
| `coverage` | PHPUnit с покрытием: изменённые строки покрыты, ни один пакет не опустился ниже своей планки |
| `mutation` | Infection на изменённых строках: тесты замечают, когда код меняется |
| `dusk` | браузерные тесты, с `--dusk` |

MySQL и PostgreSQL запускаются в Docker (`atrium-ci-mysql` на порту 33061, `atrium-ci-pgsql` на 54321, при первом запуске) или берутся с любого сервера на этих портах (`ATRIUM_CI_MYSQL_PORT`, `ATRIUM_CI_PGSQL_PORT`, `ATRIUM_CI_DB_PASSWORD`). Каждый запуск создаёт свои временные базы, поэтому `bin/ci` можно гонять из нескольких копий репозитория сразу. Без Docker обе базы пропускаются с пометкой; CI их всё равно проверит.

Для покрытия нужен Xdebug или PCOV. Шаги можно называть: `bin/ci lint static`, `bin/ci tests --db=pgsql --package=catalog`. Все параметры — `bin/ci --help`; журналы каждого процесса — в `build/ci/logs`.

## Проверки

**Каждая изменённая строка покрыта.** Исполняемые строки, которые пуш добавляет или переписывает в `packages/*/src` и `app`, должен выполнять какой-то тест. Комментарии, пустые строки и сигнатуры не считаются. Непокрытые строки печатаются по номерам, а в CI отмечаются прямо в файле.

**Покрытие не падает.** Покрытие каждого пакета, измеренное только его собственными тестами, лежит в `.ci/coverage/<пакет>`, например `87.50% of lines, 120 not covered`. CI падает, если строк пакета без теста стало больше, чем записано в файле. Процент может упасть только тогда, когда удалён покрытый код. Когда ваши тесты покрывают больше, `bin/ci` перезаписывает файл — закоммитьте его вместе с изменением, и планка поднимется для всех.

**Тесты замечают изменения.** [Infection](https://infection.github.io) портит изменённые строки — переворачивает условие, убирает вызов, возвращает другое значение — и снова запускает тесты. На каждого такого мутанта какой-то тест должен упасть. Доля пойманных мутантов (MSI) в изменённом коде — **100%**. Тест, который выполняет строку, но не проверяет, что она сделала, пропускает мутантов, и проверка не проходит. Мутанты, неотличимые от оригинала, редки; если такой мешает, перепишите код так, чтобы он исчез. Чаще всего это видимость метода: Infection делает публичный метод protected. Скоуп Eloquent объявляйте protected — Laravel вызывает его из модели; действие контроллера остаётся публичным, и его ловит `RouteActionsTest` пакета admin, если этот тест сам открывает маршрут. Infection тяжёлый, поэтому `bin/ci` запускает на одной машине не больше двух его прогонов сразу, на все рабочие копии вместе (`ATRIUM_CI_MUTATION_SLOTS`); третий ждёт.

**100%, и обойти нельзя.** Каждый пакет доводится до 100% строк и держит их, изменённый код — до 100% пойманных мутантов. Не 98 и не 99. Ни одна строка не выводится из-под проверок: `@codeCoverageIgnore` и `@infection-ignore-all` в `packages/*/src` или `app` валят шаг lint, а конфигурацию Infection пишет сам `bin/ci`, без игнора мутаторов.

**Одна обязательная проверка.** Задача `ci` в workflow `tests` проходит, только когда прошли все остальные. Для защиты ветки и очереди слияния достаточно этого одного имени.

## Что проверяют тесты модуля

Каждая добавленная или изменённая строка покрыта, и каждое условие — в обе стороны: положительный тест (то, что должно работать, работает и сохраняет, что должно) и отрицательный (ниже). Тест, который остаётся зелёным, когда строку сломали, не считается: сломайте строку один раз и убедитесь, что тест покраснел. На каждом пуше это делает за вас проверка мутациями.

Модуль тестируется снаружи — так, как им пользуются админка, сайт и API, — плюс unit-тесты для логики со многими вариантами. Для каждого модуля:

- **Основной сценарий целиком.** Создать, найти в списке, отредактировать, удалить в админке; запись на сайте; API и MCP, если они есть. Проверять то, что видит пользователь, и то, что сохранилось.
- **Каждое поле и его правила** — через набор данных (ниже).
- **Каждый способ получить отказ** (отрицательные случаи, ниже).
- **Случаи безопасности**, которые применимы (ниже).
- **Установку**: `atrium:module:install` и демо-данные, запущенные дважды, во второй раз ничего не добавляют.
- **Все языки.** В переводах есть все ключи английского, плейсхолдеры совпадают, пустых нет — во всех 15 языках: en, ru, uk, be, kk, uz, de, fr, es, pt_BR, it, pl, tr, zh_CN, ja.
- **Тест Dusk на основной путь каждого экрана** (ниже).

## Наборы данных

Один тест — много случаев. У каждого случая имя, чтобы падение говорило, какой именно:

```php
public static function names(): array
{
    return [
        'plain' => ['Garden chair', true],
        'one character' => ['A', true],
        'longest allowed' => [str_repeat('a', 255), true],
        'one too long' => [str_repeat('a', 256), false],
        'empty' => ['', false],
        'only spaces' => ['   ', false],
        'not a string' => [['array'], false],
        'Cyrillic' => ['Садовый стул', true],
        'Chinese' => ['花园椅', true],
        'Japanese' => ['ガーデンチェア', true],
        'Arabic, right to left' => ['كرسي حديقة', true],
        'Hebrew, right to left' => ['כיסא גן', true],
        'emoji' => ['Chair 🪑', true],
        'HTML' => ['<b>Chair</b>', true],
    ];
}

#[DataProvider('names')]
public function test_the_name_is_validated(mixed $name, bool $valid): void
```

Везде, где применимо:

- **правильные** значения всех видов, которые принимает поле;
- **границы**: самое короткое и самое длинное допустимое, на единицу за каждой, ноль, отрицательное, самое большое число;
- **пустое**: нет поля, `null`, `''`, пробелы, пустой массив;
- **слишком длинный** текст, слишком много элементов, слишком большой файл;
- **не тот тип**: массив вместо строки, строка вместо числа, дата, которая не дата;
- **Юникод**: кириллица, китайский и японский, арабский и иврит (справа налево), эмодзи, комбинируемые символы;
- **все 15 языков** везде, где текст показывается, сортируется, ищется, превращается в ЧПУ или переводится, — циклом по `config('atrium.locales')`.

Наборы данных статические и выполняются до запуска Laravel: в них — простые значения, записи создавайте в самом тесте.

## Отрицательные случаи

Тест, который проверяет только удачный путь, проверяет половину. Для каждого действия ещё:

- **Ошибки проверки**: ошибка показана у нужного поля, и ничего не сохранилось.
- **Нет прав**: администратор без права получает 403 на список, форму, сохранение, удаление и API — а не только не видит кнопку.
- **Чужой сайт**: запись сайта B никогда не видна, не открывается, не редактируется и не находится поиском на сайте A — ни в админке, ни на сайте, ни в API.
- **Удалённые и неактивные записи**: их нет на сайте, в sitemap и поиске, по старому адресу — 404 (или редирект, если модуль его обещает).
- **Одновременная запись**, где она возможна: счётчики, порядок сортировки, уникальные коды — два сохранения одной записи, две отправки сразу.
- **Отсутствующее**: неизвестный id — 404, пропавшая связанная запись не роняет страницу, неустановленный модуль не нужен.
- **Внешний сервис не ответил**: ошибка, таймаут (`Http::fake()` с 500 и с `ConnectionException`) — пользователь видит понятное сообщение, ничего не сохранилось наполовину, сбой записан в журнал.

## Безопасность

- **XSS**: `<script>alert(1)</script>`, `"><img src=x onerror=alert(1)>` и ссылки `javascript:` в каждом текстовом поле возвращаются экранированными на сайте и в админке. Из HTML-полей вычищаются скрипты и атрибуты событий.
- **Массовое присваивание**: отправка `id`, `site_id`, `created_by`, `is_superadmin` и любых полей, которых нет в форме, ничего не меняет.
- **Загрузка файлов**: сохраняются только разрешённые типы, определённые по содержимому, а не по имени (`photo.jpg`, внутри которого PHP, отклоняется); слишком большие файлы отклоняются; имена с `../` и Юникодом сохраняются безопасно.
- **Подписанные ссылки**: ссылка без подписи, с изменённым параметром или после срока отклоняется.
- **Вход и CSRF**, где модуль добавляет формы на сайт: запрос без токена отклоняется, ограничения на попытки работают.

## Браузерные тесты

У каждого экрана есть тест Dusk на основной путь: открыть, заполнить как пользователь, сохранить, увидеть результат и проверить базу. Элементы выбираются по атрибутам `dusk="…"`, никогда по CSS-классам или тексту, который меняет перевод. Никаких `pause()` на время: ждите то, что ожидаете (`waitForText`, `waitFor`, `waitUntilMissing`). Тесты Dusk лежат в `tests/Browser` и запускаются через `bin/ci --dusk`.

## Как писать тесты

- **PHPUnit**, не Pest. Тесты пакета — в `packages/<имя>/tests`: `Feature` для HTTP и команд, `Unit` для отдельных классов.
- **Имя говорит, что происходит**: `test_an_administrator_without_the_right_cannot_delete_a_product`, а не `test_delete_2`.
- **Подготовка, действие, проверка**, одно поведение на тест. Проверяйте результат — ответ, сохранённую строку, отправленное письмо, — а не то, что вызвался метод.
- **Записи** создают фабрики моделей пакета (`packages/<имя>/database/factories`) или помощник тестового класса; демо-сидер — только если тест про демо.
- **Без пауз, часов и случайности**: `$this->travelTo()`, `Str::createUuidsUsing()`, фиксированные зёрна.
- **Без сети**: `Http::fake()`, `Mail::fake()`, `Queue::fake()`, `Storage::fake()`. Тест, который ходит в интернет, в CI упадёт.
- **Без порядка между тестами**: каждый начинает с пустой базы и ничего после себя не оставляет. Тесты пакета идут в своём процессе со своим приложением, параллельно с другими пакетами.
- **Все базы**: тесты идут на SQLite, MySQL и PostgreSQL. Не полагайтесь на сортировку, регистр или JSON одной из них; сортируйте явно.

## Если проверка не прошла

- **Не покрыто**: в сообщении номера строк. Напишите тест, который их выполняет и проверяет, что они делают. Если строка недостижима — удалите её.
- **Покрытие упало**: вы убрали тесты или добавили код без них. Какой файл потерял покрытие — в `build/ci/coverage/<пакет>`.
- **Мутанты выжили**: `build/ci/infection/<пакет>/infection.log` показывает каждого — изменение, которое сделал Infection и которого не заметил ни один тест. Добавьте проверку, которая бы его поймала.
- **Красное только в CI**: запустите ту же ветку: `bin/ci tests --db=mysql`. Журналы всех задач CI прикрепляются к запуску, если он упал.
