# Расширения: платформа

[English](extensions.md) · [Русский](extensions.ru.md)

Это проект Atrium как платформы: продукта, который другие расширяют снаружи, как в маркетплейсе, и в котором человек без навыков программирования сам собирает себе проект прямо в админке. Сначала — что уже есть в коде, потом — чего не хватает на четырёх уровнях, в конце — порядок пул-реквестов, которыми это строится.

Это проект, а не руководство: построенное отмечено словом **готово** с номером пул-реквеста, а справочником по тому, что работает сегодня, остаются руководства ([модули](modules.ru.md), [свои поля](custom-fields.ru.md), [интеграции](integrations.ru.md)).

## Принципы

1. **Одни точки расширения на всех.** То, что Atrium делает сам, идёт через те же точки, что и плагин: свои гаджеты рабочего стола, события и действия Atrium регистрирует так же, как чужие. Точка, которой Atrium не пользуется сам, гниёт.
2. **Каждый уровень стоит на нижнем.** Конструктор создаёт то же определение, что регистрирует плагин на PHP; внешнее приложение видит те же события и тот же API, что и плагин. Сущность, собранная мышкой, ищется, импортируется, выгружается, получает API и историю точно так же, как модуль из кода: эти возможности читают модуль, и им всё равно, кто его написал.
3. **Данные раньше кода.** Что может быть данными, то и есть данные: сущность, поле, вид, статус, правило. Данные хранятся в базе, выгружаются шаблоном, раздаются через Маркет и ставятся без Composer.
4. **Безопасно по устройству.** Конструктор и формулы не могут выполнить код. Плагину на PHP доверяют: его ставит суперадмин через Composer, как любой пакет. Внешнему приложению не доверяют: оно видит только то, что разрешают его области прав, а его экраны живут во фрейме.
5. **Своего языка нет.** Формулы — на готовом языке выражений с песочницей (Symfony ExpressionLanguage). Если когда-нибудь понадобятся скрипты, в песочницу встраивается известный язык (Lua или JavaScript); свой Atrium не изобретает.
6. **Те же планки.** Всё здесь выходит с покрытием и MSI 100%, на 15 языках, с контрастом от 4,5:1 и никогда с цветом как единственным признаком.

Итого база хороша для программиста, который пишет модуль: хуки, реестры и фильтры `atrium.module.*` дотягиваются снаружи почти до любой части панели. Всем остальным не хватает трёх вещей: **списка событий**, из которого может выбрать человек или другая программа; способа пакету принести **свой интерфейс** в собранную админку; **сущностей-данных**, а не сущностей-кода.

## Контракты ядра

Четыре контракта — публичный API платформы. Их имена и состав данных идут по семантическому версионированию: в 0.x минорная версия может их поменять и пишет об этом в журнале изменений; с 1.0 поля только добавляются.

### Каталог событий

Каждое событие, которое может услышать подписчик, объявляется один раз — с подписью и составом данных. Модули запускают хуки как и сейчас (`Hook::fire('atrium.tracker.task.status_changed', $task, $from, $to)`), а объявление говорит, что этот хук значит для внешнего мира.

```php
use Atrium\Admin\Extensions\Event;
use Atrium\Admin\Facades\Hook;

// В boot() сервис-провайдера, пока модуль установлен:
Hook::register('atrium.events', 'tracker.task.status_changed', Event::make('atrium.tracker.task.status_changed')
    ->label('atrium-tracker::events.status_changed')   // текст или ключ перевода
    ->subject(Task::class)                              // первый аргумент — запись
    ->payload(fn (Task $task, string $from, string $to): array => ['from' => $from, 'to' => $to]));
```

- **Ключ** (`tracker.task.status_changed`) видят люди и программы: в правиле автоматизации, в подписке вебхука, в API. **Хук** — имя, которое запускает модуль.
- **Предмет** — запись, о которой событие. Он решает, кто может его услышать: вебхук или приложение получают событие, только если могут читать модуль предмета; правило срабатывает только на записи, которые ему видны.
- **Данные** — простой JSON из аргументов хука; это то, что уходит в вебхук. Секретов в них быть не должно.
- **События записей** ядро объявляет для каждого модуля само, писать ничего не надо: `{module}.created`, `{module}.updated`, `{module}.deleted` (`products.created`, `deals.updated`), из `atrium.record.saved` и `atrium.record.deleted`. Сущность из конструктора получает их в момент создания. Когда журнал ([#115](https://github.com/AlveBy/atrium/pull/115)) будет в `main`, `updated` станет нести ещё и имена изменившихся полей.
- Когда срабатывает объявленный хук, каталог превращает его в **случай** (occurrence) и запускает одно действие `atrium.event.occurred`. Правила автоматизации, вебхуки и приложения слушают только его. У случая есть id (для идемпотентности), ключ, предмет (модуль и id), данные, кто это сделал (пользователь, приложение или никто), сайт и время.

```json
{
  "id": "0f9f2a8e-6c1b-4a0e-9d55-8b6a8f0d1e23",
  "event": "tracker.task.status_changed",
  "occurred_at": "2026-11-25T10:15:00+00:00",
  "site": 1,
  "actor": {"type": "user", "id": 7},
  "subject": {"module": "tasks", "id": 42},
  "data": {"from": "todo", "to": "in_progress"}
}
```

Каталог показывает `php artisan atrium:events`, позже — `GET /api/v1/events` и экран правил.

### Места в панели

Поля, колонки, фильтры, вкладки, кнопки записи и массовые действия, кнопки над списком и пункты меню панель уже берёт из любого пакета (фильтры `atrium.module.*`). Добавляются три места, и встроенное переезжает на них же:

| Место | Реестр | Где рисуется |
|---|---|---|
| Гаджет рабочего стола | `atrium.ui.gadgets` | Плитка на стартовой странице; встроенные гаджеты регистрируются здесь же, `atrium.dashboard.gadgets` остаётся раскладкой |
| Панель записи | `atrium.ui.panels` | Блок рядом с формой записи или под ней, или своя вкладка; для одного модуля или для всех |
| Экран | `atrium.ui.pages` | Своя страница в панели с пунктом меню и правом |

Показывает такое место один из трёх видов **содержимого**:

- **HTML** с сервера (вид Blade), как у `DisplayField`. Работает без сборки.
- **Компонент**: компонент Vue из собственного собранного ES-модуля пакета. Админка отдаёт таким модулям Vue, Inertia, свои компоненты и переводы (`window.Atrium`), поэтому пакет не пересобирает админку: он публикует свой файл в `public/vendor/{package}` и называет его в реестре `atrium.ui.scripts`.
- **Фрейм**: страница внешнего приложения в `<iframe>` с подписанным контекстом (см. [уровень 4](#уровень-4-внешние-приложения-на-любом-языке)).

У каждого места есть право (`->permission('tracker.view')`), условие (`->when(fn (Model $record, AdminUser $user): bool => …)`) и порядок.

### Действия

Что может сделать правило — реестр `atrium.automation.actions`, и встроенные действия лежат в нём же: поменять поле, перевести в статус, создать запись, уведомить, отправить вебхук, нажать кнопку записи (любой `RecordAction`, который у модуля уже есть), подождать. Плагин добавляет свои: класс с настройками, которые показывает конструктор (поля — те же классы `Field`, что у формы), и `run(Occurrence $occurrence, array $settings)`.

### Типы полей

Типы своих полей сейчас — enum (`string`, `text`, `number`, `decimal`, `boolean`, `date`, `select`, `multiselect`, `link`, `file`, `image`). Они становятся реестром `atrium.fields.types`: каждый тип говорит, как хранится и нормализуется значение, каким полем формы рисуется, как фильтруется, сортируется, импортируется, выгружается и описывается в API. Деньги, телефон, рейтинг, статус, формула, связь с пользователем — типы, добавленные так, встроенные в том числе.

## Уровень 1. Без кода: конструктор

Главный уровень. Планку задают смарт-процессы Битрикс24, Airtable и Notion. Раздел **Конструктор** в админке — для суперадмина и ролей с правом `builder.manage`.

### Сущности

Сущность — раздел панели, собранный мышкой: «Сделки», «Кандидаты», «Объекты», «Заявки». У неё есть название на языках контента, ключ, значок, место в меню и переключатели: разделы (дерево), страницы на сайте, свои для каждого сайта, переводимая, SEO, файлы.

**Хранение.** Каждая сущность — настоящая таблица `atrium_entity_{key}`, которую конструктор создаёт с системными колонками: `id`, `site_id`, `name`, `status`, `sort`, `active`, `created_by`, `updated_by`, даты и JSON-колонка `custom`. Поля, которые добавляет человек, — **свои поля**: то же хранение, фильтры, фасеты, сортировка, поиск и «горячие» настоящие колонки, что у модуля из кода. То есть конструктор — это «пустой модуль плюс свои поля». Таблица на сущность, а не одна на всех: свои индексы, свой размер, выгрузка или удаление — это одна таблица, и так же Битрикс24 хранит смарт-процессы.

**Класс на сущность.** Панель знает свои модули по классу Eloquent: маршруты, права, morph map, API и импорт читают статические методы класса. Конструктор пишет на каждую сущность класс в две строки (`final class Deal extends Atrium\Builder\Entity {}`) в `bootstrap/cache/atrium-entities`, его загружает автозагрузчик; если файла нет, он создаётся заново из базы (`php artisan atrium:entities:cache`). Без `eval`. `Entity` реализует `Administrable` и читает поля, колонки, вкладки и виды из определения в базе (с кешем). Дальше поиск, импорт и экспорт, API и MCP, журнал и версии, корзина, канбан и права работают для неё как для любого модуля, без строчки своего кода.

**Связи.** Поле может ссылаться на другую сущность или на модуль из кода (товар, задачу, пользователя): на одну запись (колонка `{field}_id`) или на несколько (одна общая таблица `atrium_entity_links`: откуда, поле, куда). У связанной записи во вкладке виден список её связей.

**Списки, формы и виды.**

- Колонки: какие, в каком порядке, сортировка по умолчанию; сохранённые виды («Мои сделки», «Просроченные») для пользователя или роли.
- Формы: вкладки и порядок полей мышкой, обязательность, подсказки, значения по умолчанию и видимость по формуле.
- Виды: **таблица**, **канбан** по статусу или полю-списку и **календарь** по полю-дате. Это классы `View` из [#116](https://github.com/AlveBy/atrium/pull/116) (`KanbanView` и будущий `CalendarView`), так что календарь получит и модуль из кода. Вид переключается над списком.

### Статусы и переходы

Тип поля **статус**: стадии с названием, цветом и значком (никогда не только цветом), финальные стадии с отметкой «успех» или «провал»; из какой стадии в какую можно перейти; каким ролям можно двигать запись; какие поля нужно заполнить, чтобы войти в стадию; что происходит при входе (правило). Колонки канбана — это стадии.

### Правила «когда → если → сделать»

У правила есть **запуск**, **условие** и **шаги**:

- **Когда**: событие из каталога (любого модуля, свои у сущностей конструктора: `deals.created`, `deals.updated`, смена статуса), по расписанию («каждый понедельник в 9:00») или при наступлении даты из поля («за 3 дня до `due_at`»).
- **Если**: условие на [языке формул](#уровень-2-формулы-и-условия): `record.amount > 10000 and record.status == "won"`.
- **Сделать**: шаги из реестра действий, по порядку, с паузами («через 2 часа»).

Правила идут в очереди, по одному на запись, и каждый запуск пишется в журнал с итогом. Запуск идемпотентен для случая; правило не запускает само себя глубже заданного числа уровней; правило можно проверить на выбранной записи, ничего не меняя.

**Роботы-уведомления** — правила, у которых шаг «уведомить»: кого (пользователя, роль, человека из поля, автора), как (уведомление в панели, почта; Telegram и другие — плагинами) и что (текст с полями записи).

### Роли

Права, которые есть у каждого модуля (просмотр, создание, изменение, удаление и свои), у сущности появляются сразу, в форме роли. Добавляются два для всех модулей, и конструктора, и из кода: **только свои записи** (по автору или полю «ответственный») и **по полям** (скрыто или только чтение для роли).

### Шаблоны проектов

Шаблон — проект в одном файле: сущности, поля, связи, виды, статусы, правила, роли, меню, рабочий стол и, по желанию, примеры записей, с нужными пакетами (`"requires": {"alveby/atrium-tracker": "^0.3"}`) и текстами на 15 языках. Ставится одним кликом — из Маркета или из файла; новая версия показывает, что поменяет, прежде чем поменять; при удалении спрашивает, оставить ли данные. Проект, собранный в конструкторе, выгружается в шаблон одной кнопкой, так что шаблоны делаются тем же путём, что и всё остальное. Первые: воронка продаж, подбор персонала, служба поддержки, агентство недвижимости, мероприятия.

Шаблон — данные, а не код: ставится без Composer, им можно свободно делиться. Публикуется файлом JSON или пакетом Composer типа `atrium-template` (файл и переводы).

### Маркет

Экран **Модули** становится **Маркетом**: один каталог модулей, плагинов, шаблонов и приложений — с Packagist (типы `atrium-module`, `atrium-template`) и из индекса на сайте Atrium, который добавляет описания, скриншоты и отметку «проверено Atrium». Шаблоны и приложения ставятся прямо с экрана. Пакету на PHP нужен Composer, а запускать Composer из веб-запроса небезопасно и на большинстве хостингов не работает, поэтому экран по-прежнему показывает команды, а сайт, который это разрешил (`atrium.market.composer`), получает кнопку: она запускает их фоновой задачей после подтверждения суперадмином вторым фактором.

## Уровень 2. Формулы и условия

**Решение принято**: [Symfony ExpressionLanguage](https://symfony.com/doc/current/components/expression_language.html). Это готовый, хорошо проверенный язык с песочницей: нет присваиваний, циклов и вызовов функций PHP — только переменные и функции, которые ему дали, а разобранные выражения кешируются. Свой язык Atrium не пишет.

Где нужны формулы:

- **вычисляемые поля** (тип поля `formula`, значение сохраняется при записи, чтобы списки по нему фильтровались и сортировались): `record.price * record.quantity`, `days_between(record.start, record.end)`;
- **условия** правил, переходов между стадиями и видимости полей;
- **значения по умолчанию**: `today() + days(14)`;
- **проверки**: `record.end >= record.start` с текстом ошибки.

Переменные: `record` (поля по коду), `old` (значения до изменения), `user`, `site`, `now`. Функции: даты (`today`, `days`, `days_between`, `format_date`), текст (`lower`, `upper`, `contains`, `concat`), числа (`round`, `min`, `max`, `sum`), проверки (`has_role`, `in_stage`). Плагин добавляет функции в реестр `atrium.expressions.functions`.

Безопасность: выражение видит массивы и простые значения, но не объекты (ExpressionLanguage позволил бы вызывать их методы); длина ограничена; ошибку выражения видит тот, кто его написал, а не посетитель. Редактор подсказывает переменные и поля, проверяет выражение при сохранении и показывает его значение на выбранной записи.

Скрипты не планируются. Если понадобятся, в песочницу встраивается известный язык (Lua через LuaSandbox или JavaScript через QuickJS) с ограничением времени и памяти.

## Уровень 3. Плагины на PHP

Плагин — пакет Composer типа `atrium-module`, как и модуль: модуль с моделями — тоже плагин, а у плагина моделей может не быть вовсе. Он есть в Маркете и ставится как модуль. Всё, что он добавляет, регистрируется в `boot()` его сервис-провайдера, пока он установлен, — через контракты ядра и хуки:

```php
public function boot(): void
{
    if (! app(Modules::class)->isInstalled('acme/atrium-tracker-time')) {
        return;
    }

    // Своё событие — для правил, вебхуков и приложений:
    Hook::register('atrium.events', 'time.logged', Event::make('atrium.time.logged')
        ->label('acme-time::events.logged')->subject(TimeEntry::class));

    // Слушать событие другого модуля:
    Hook::on('atrium.tracker.task.status_changed', StopTimerWhenDone::class);

    // Колонка в списке задач трекера и панель рядом с задачей:
    Hook::filter('atrium.module.columns', AddLoggedColumn::class);
    Hook::register('atrium.ui.panels', 'time.task', Panel::make('time.task')->for(Task::class)
        ->label('acme-time::panels.time')->html('acme-time::panels.task'));

    // Гаджет, действие для правил и функция для формул:
    Hook::register('atrium.ui.gadgets', 'time.week', WeekGadget::class);
    Hook::register('atrium.automation.actions', 'time.log', LogTime::class);
    Hook::register('atrium.expressions.functions', 'logged_hours', LoggedHours::class);
}
```

- Контракты (`Atrium\Admin\Extensions\*`) и ключи каталога событий — публичный API. Плагин требует версию, под которую написан (`"alveby/atrium": "^0.3"`).
- Интерфейс плагина — HTML из Blade или компоненты Vue из его собственного собранного модуля (см. [содержимое](#места-в-панели)). Такой модуль собирает пресет Vite, оставляя Vue и админку снаружи.
- Тестируется через Orchestra Testbench, как пакеты Atrium, с теми же планками.
- Плагин — доверенный код: он работает внутри сайта. Поэтому его ставит суперадмин через Composer, а Маркет отмечает те, что Atrium прочитал.

## Уровень 4. Внешние приложения на любом языке

Как приложения Connect у Jira: приложение работает на своём сервере, на любом языке, и общается с Atrium только по HTTP. Сломать сайт оно не может и видит только то, что ему разрешили.

- **Регистрация.** В разделе **Приложения** суперадмин добавляет приложение по адресу его манифеста (`atrium-app.json`: название, значок, адреса, нужные области прав, нужные события, панели) или из Маркета. Экран установки перечисляет, что приложение увидит и сможет; ставится оно только после подтверждения.
- **OAuth 2.0** с кодом авторизации и PKCE, токены на установку. **Области прав** — это нынешние права токенов (`{module}:read`, `{module}:write`) плюс `events:read`, `webhooks:write`, `ui:panels`. Токен не даёт больше своих областей и больше, чем было у установившего пользователя.
- **Вебхуки.** Приложение (или человек в админке) подписывается на ключи каталога. Каждый случай уходит JSON-ом, как выше, через очередь `alveby/atrium-integrations` (повторы, журнал обмена, оповещения) и с подписью: `X-Atrium-Signature: sha256=HMAC(secret, timestamp + "." + body)`, время и id случая — в заголовках, чтобы были видны повтор и дубль. Подписка, которая подряд отказала заданное число раз, ставится на паузу, а владельцу приходит сообщение. Событие уходит, только если приложение может читать модуль его предмета.
- **Панели во фрейме.** Панель, гаджет или экран приложения — это фрейм в одном из [мест панели](#места-в-панели). К его адресу добавляется короткоживущий токен, подписанный секретом приложения (JWT, HS256, пять минут): сайт, пользователь, приложение, место, запись (модуль и id), язык и цветовая тема. Приложение проверяет токен и ходит в REST API со своим токеном. Небольшой скрипт (`atrium-app-bridge.js`) даёт фрейму поменять высоту, показать сообщение, открыть страницу панели и попросить форму перечитать запись. Фрейм в песочнице, а `frame-src` панели разрешает только адреса самого приложения.
- **REST API.** То, что есть, плюс `GET /events`, подписки, `GET /me`; сущности конструктора попадают в OpenAPI сами.

Приложения, работающие на серверах Atrium, как Forge у Atlassian, не планируются: для них нужна среда исполнения в песочнице и свой хостинг.

## Безопасность

| Уровень | Доверие | Что ограничивает |
|---|---|---|
| Конструктор | Человек с правом `builder.manage` | Создаёт только данные; те же права, что у любого модуля; кода нет |
| Формулы | Любой, кто может править правило или поле | ExpressionLanguage только с выданными переменными и функциями, без объектов, с ограничением длины |
| Плагин на PHP | Полное, как у любого пакета | Ставит суперадмин; отметка Маркета; требуемая версия |
| Внешнее приложение | Никакого | Области прав OAuth, права установившего пользователя, подписанные вебхуки, фрейм в песочнице, подписанный контекст с коротким сроком жизни |

## Пул-реквесты по порядку

Каждый пул-реквест небольшой и полезен сам по себе — со своими тестами, документацией и 15 языками. Первые — то, что нужно плагинам Atrium Tracker (`packages/tracker`).

| № | Пул-реквест | Чем полезен сразу |
|---|---|---|
| 1 | Этот проект (`docs/extensions.md`, `.ru.md`) | Все строят по одному плану |
| 2 | **Каталог событий**: `Event`, реестр `atrium.events`, события записей для каждого модуля, `Occurrence`, `atrium.event.occurred`, `php artisan atrium:events` | Трекер объявляет свои события; любой пакет слышит `deals.created`, не разбирая каждое сохранение |
| 3 | **Гаджеты из пакетов**: реестр `atrium.ui.gadgets`, HTML, встроенные гаджеты переезжают на него | Пакет (у трекера — «Мои задачи», «Время за неделю») ставит плитку на рабочий стол |
