# План развития Atrium

[English](ROADMAP.md) · **Русский**

Atrium — админка для Laravel, которая ставится одной командой, ведёт сколько угодно сайтов и с первого дня говорит на 15 языках. Здесь — куда проект идёт после первого выпуска. Сроков нет, есть порядок: модули → импорт с других CMS → магазин → 1С и Битрикс24. Каждая следующая версия опирается на предыдущую: импорт, магазин и интеграции сами — модули.

## Принципы

- **Всё, что сверх ядра, — модуль.** Магазин, галерея, импорт с WordPress, связка с 1С — отдельные пакеты. Ядро остаётся маленьким, лишнее не ставится.
- **Модуль ставится, а не дописывается.** `composer require` и одна команда — модуль появился в меню, таблицы созданы, демо-данные есть. Никаких правок кода в проекте.
- **Каждый модуль сразу умеет то же, что ядро:** 15 языков интерфейса, переводимый контент, несколько сайтов, тесты PHPUnit и Dusk.
- **Переезд — тоже функция.** Для каждой популярной CMS свой импорт с отчётом «было/стало» и картой 301-редиректов, чтобы сайт не потерял поиск.

## 0.1 — первый выпуск (идёт сейчас)

Ядро админки уже перенесено и покрыто тестами. Осталось:

- языки интерфейса (15), переключатель у каждого админа;
- ~~языки контента~~ готово: язык добавляется из админки, колонки модели перечисляются в `$translatable`, у каждого языка свои адреса `/de/…` и `hreflang`;
- несколько сайтов в одной админке, сайт определяется по домену;
- мигратор с 1С-Битрикс (`alveby/atrium-bitrix`);
- нейтральная тема сайта (`alveby/atrium-theme`), светлая и тёмная;
- демо-данные: `php artisan atrium:install --demo`;
- README на 15 языках.

Документация к выпуску (Markdown в репозитории, `docs/`):

- **Установка** — на свой сервер, на обычный хостинг с панелью (ISPmanager, cPanel: без Docker и без SSH-доступа к Node), в Docker.
- **Настройка** — конфиг, почта, двухфакторный вход, API-токены, файлы.
- **Свой модуль** — от `atrium:make-module` до пакета на Packagist: поля, колонки, вкладки, права, переводы, тесты.
- **Переезд с Битрикса** — по шагам, с проверкой `atrium:bitrix:parity`.

## 0.2 — модули, которые просто устанавливаются

Основа для всего остального: магазин, импорт и интеграции сами будут модулями.

**Механика**
- Модуль — composer-пакет с `"type": "atrium-module"` и описанием в `extra.atrium`: что регистрирует (ресурсы, меню, права, настройки, миграции, демо-сидер).
- `php artisan atrium:module:install {name}` / `atrium:module:remove {name}` — миграции, ассеты, права, пункт меню; удаление спрашивает, оставить ли данные.
- Экран «Модули» в админке: установленные (включить, выключить, настроить) и доступные — каталог с Packagist по типу `atrium-module`, с описанием на языке админа и командой установки.
- Шаблон-репозиторий модуля: структура, тесты, CI, переводы — «нажал Use this template и пишешь».

**Что нужно модулям от ядра**
- Роли и права: кто какой модуль видит и что может (смотреть, править, удалять), с ограничением по сайтам.
- Настройки модулей: экран настроек, который модуль описывает полями так же, как форму записи.
- События и хуки: «запись сохранена», «заявка пришла», «заказ оплачен» — чтобы модули общались, не зная друг о друге.
- Очереди и журнал: фоновые задачи модулей с повтором и экраном ошибок.

**Официальные модули**
| Модуль | Что делает |
|---|---|
| Страницы | Статические страницы с деревом и шаблонами |
| Новости / Блог | Лента, рубрики, теги, RSS |
| Галерея | Альбомы фотографий и видео на сайте |
| Формы и заявки | Конструктор форм, заявки в админке, письма, антиспам |
| Меню | Меню сайта мышкой, на каждый сайт и язык своё |
| Баннеры и слайдеры | Места на страницах, расписание показа |
| Отзывы | С модерацией и рейтингом |
| Вопросы и ответы | FAQ с разметкой для поисковиков |
| SEO | Редиректы, sitemap.xml, robots.txt, метатеги по шаблону |
| Поиск | По всем модулям сайта, с учётом языка |
| Медиабиблиотека | Общая библиотека файлов с папками (сейчас — часть ядра) |

## 0.3 — переезд с других CMS

Мигратор Битрикса обобщается в `alveby/atrium-import`: один конвейер, разные источники.

**Общий конвейер для любого источника**
1. Анализ: что есть в старой базе — типы записей, поля, разделы, языки, сайты.
2. Модули: по найденному создаются модели и формы админки.
3. Данные: записи, файлы, SEO, пользователи.
4. Проверка: отчёт «было/стало» по каждой таблице и полю — пустой отчёт значит «ничего не потеряли».
5. Адреса: карта 301-редиректов со старых URL на новые.
6. Догоняющая синхронизация: пока старый сайт работает, переносятся только изменения.

**Источники**
| CMS | Что переносим |
|---|---|
| 1С-Битрикс | уже есть: инфоблоки, разделы, свойства, раскладка форм, медиабиблиотека, SEO |
| WordPress | из выгрузки WXR и напрямую из базы; записи, страницы, рубрики, метки, произвольные типы записей, ACF, Yoast/Rank Math, мультиязычие WPML/Polylang |
| Drupal | 7 (снят с поддержки — больше всего желающих уехать) и 10/11; ноды, таксономия, поля, пути |
| Joomla | материалы, категории, меню |
| MODX | ресурсы, TV-поля |
| Tilda | из экспорта: страницы и картинки |

Порядок после WordPress — по запросам в Issues.

## 0.4 — интернет-магазин

`alveby/atrium-shop` и модули к нему. Каждый ставится отдельно: нужен только каталог с заявками — ставите только каталог.

**Основа**
- Каталог: товары, разделы, свойства, фильтр, торговые предложения (размер, цвет), остатки по складам.
- Цены: несколько типов цен, валюты с курсами, налоги.
- Корзина и оформление заказа, личный кабинет покупателя, история заказов.
- Заказы в админке: статусы, письма покупателю на каждый статус, печать.

**Оплата и доставка** (каждый способ — отдельный модуль)
- Оплата: Stripe, ЮKassa, bePaid, CloudPayments; другие — по запросу или от сообщества.
- Доставка: самовывоз, курьер, зоны и тарифы; службы доставки — модулями.

**Маркетинг**
| Модуль | Что делает |
|---|---|
| Скидки | Правила: на товар, раздел, корзину, от суммы, для групп покупателей |
| Купоны | Одноразовые и многоразовые коды, лимиты, сроки |
| Бонусы | Начисление за заказ, оплата частью заказа, уровни лояльности |
| Акции | Страница акции с товарами, сроками и таймером |
| Подарочные сертификаты | Продажа и погашение |
| Избранное и сравнение | |
| Отзывы о товарах | Рейтинг, фото, «купил — может оставить отзыв» |
| Брошенные корзины | Напоминание письмом |
| Выгрузки | Яндекс.Маркет (YML), Google Merchant |

**Переезд магазина** — из Битрикса (модуль «Интернет-магазин»), WooCommerce, OpenCart: товары, предложения, цены, остатки, покупатели, заказы.

## 0.5 — 1С и Битрикс24

**1С**
- Обмен по стандартному протоколу CommerceML 2 — тому же, что у Битрикса. Типовые конфигурации 1С (УТ, УНФ, КА и другие) подключаются к Atrium без доработок со стороны 1С: меняется только адрес сайта в настройках обмена.
- Из 1С: каталог, свойства, картинки, цены, остатки. В 1С: заказы и их статусы.
- Экран обмена в админке: когда был последний, что пришло, ошибки.

**Битрикс24**
- Заявки с форм и заказы — в лиды или сделки, покупатели — в контакты.
- Статусы сделки — обратно на сайт (заказ оплачен, отгружен).
- Виджет открытых линий / онлайн-чата Битрикс24 на сайте.
- Подключение через входящий вебхук: вставили адрес — работает.
- Связка «форма → лид» — простая и нужна почти всем, поэтому может выйти раньше, вместе с модулем «Формы» в 0.2.

**Общее для интеграций:** очередь с повторами, журнал обмена, уведомление админу при сбое. На этой же основе потом — amoCRM, «МойСклад» и другие по запросу.

## Сайт проекта и документация

Адрес — **atrium.alve-soft.com**. Параллельно с 0.2, как только есть модули «Страницы», «Меню» и «Поиск».

- Сайт сделан на самом Atrium — лучшая демонстрация и проверка, что всё работает.
- 15 языков, как у админки.
- Документация — те же Markdown-файлы из `docs/` репозитория; сайт их рендерит модулем «Документация», версии — по выпускам. Исправить опечатку = пулл-реквест в репозиторий.
- Онлайн-демо админки: зашёл без регистрации, всё можно трогать, база сбрасывается каждый час.
- Каталог модулей: официальные и от сообщества, с языками, версиями и командой установки.
- До запуска сайта документация живёт на GitHub.

## 1.0 — стабильная версия

- Публичный API ядра заморожен: модули, написанные под 1.x, работают на всех 1.x.
- Руководство по обновлению с 0.x.
- Аудит безопасности.
- Политика поддержки: какие версии Laravel и PHP, сколько живёт каждая версия Atrium.

## Как пакеты попадают на Packagist

Разработка — в одном репозитории (монорепо), каждый пакет при выпуске автоматически выкладывается в свой репозиторий только для чтения (`AlveBy/atrium-shop` и т. п.), оттуда его берёт Packagist. Пользователь ставит только то, что нужно.
